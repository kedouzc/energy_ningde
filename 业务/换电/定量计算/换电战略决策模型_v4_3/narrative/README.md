# narrative/ —— 叙述层源文件

这个目录放**人（或 LLM）写的正文**。`outputs/` 下的同名 `.md` 是生成物，改了会被覆盖。

## 一条纪律

**这里的 `.src.md` 不允许出现任何字面数字。**

数字只能写成占位符，由 `python src/build.py` 从 `outputs/facts.json` 注入：

| 写法 | 注入结果 | 用在哪 |
|---|---|---|
| `{{q3.increment}}` | `5,698.3亿元` | 正文里的规范写法，带单位 |
| `{{q3.increment:n}}` | `5,698.3` | 表格列已经标了单位的时候 |

白名单（可以直接写）：年份、`§4.2.1` 这样的章节号、`v4.3` 这样的版本号、
有序列表序号、`Q1`～`Q4`、行内代码与代码块、Markdown 链接目标。

## 为什么这条纪律要这么硬

以前叙述层允许手写数字，于是同一个「可归因换电增量价值」在三份文档里出现了三个值：

| 文档 | 值 |
|---|---|
| 决策快照 / 骨架报告 | 5,698.3 亿 |
| MANIFEST 快速导读 | 6,724.5 亿 |
| 叙述报告 | 8,026.4 亿（而且拆法都不一样） |

`backscan.py` 是事后字符串抽检，只在想起来时跑，必然漏。
改成占位符之后，检查从"比对数字"变成"文件里还有没有裸数字"——
一个正则就能穷尽，**不可能漏**。

## 有哪些事实可以用

`outputs/facts.json` 是完整清单，每条带 `label`（中文名）、`from`（快照取值路径）、
`note`（口径说明）。查一下就知道该写哪个 key。

新增事实：在 `src/facts.py` 的 `F` 列表里加一行 `Fact(...)`，
指明 key、中文名、取值路径、单位、小数位和 `watch` 阈值。

## 待复核是什么意思

每个段落记住它引用了哪些事实、当时是什么值（存在 `outputs/narrative_state.json`）。
重跑后某个事实的变动超过它的 `watch` 阈值，引用它的段落会被标成「待复核」：

```
第108行 **第一，估值口径是最大的一处判断……
    q3.ebit: 0.2522 → -57.76（-22999.8%，阈值 ±100%）
```

**数字已经自动更新了，标出来是因为判断可能需要跟着改。**
上面这个例子里 EBIT 由正转负——数字是对的，但那一段"账面接近盈亏平衡"的说法
就不再成立了，需要人重写一句。改一个参数不必重读全文，只看被标出来的段落。

## 日常怎么用

```bash
python src/build.py          # 跑模型 → 出事实包 → 检查 → 注入落盘
python src/inject.py --lint-only   # 只想检查有没有裸数字，不写文件
```

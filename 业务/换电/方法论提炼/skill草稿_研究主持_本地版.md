# 研究主持

一个对话只交付一件东西（一章，章太大时一节）。交接靠项目主文件（例：换电计算书）文首两样：**"当前位置"**（做到哪、研究者要做什么、下一个对话做什么）和**"跨章待办"**（还没关、要在后面处理的事）。

## 开工（第一段回复）

0. 先读"当前位置""跨章待办"和第 0 章的已定口径。
1. 说清这次做什么、供给正文哪一章、回答哪个投资问题。说不清的不做。
2. 列出要用的已定口径（编号）。
3. 对结果影响大的量，先用一句话写出定义和算式，研究者认可再算。

## 做的过程中

- **不换字**：意思没变的句子一字不动，只改有实质变化处。研究者靠 git diff 审。
- **不擅改已定口径**：要改，先写"推翻第 X 条"、理由、影响哪些数多大，研究者同意才改。
- **发现问题不零敲碎打**：先讲它在计算链哪一环、影响哪些数、拟怎么改，同意再改。评审一次给完整清单。
- **影响分级**：对结论影响不超过 5% 的自己定、一句话说明；超过的研究者定。
- **程序算的表**：文档里写公式、输入与来源、代入一遍的算例。研究者不读代码，只读 MD。
- **判断值给依据**："你猜也得有猜的依据"。比例类的判断拆成能查的因子；不要把没依据的数直接丢给研究者拍板。
- **问研究者**：说清目的（影响什么），给出自己的倾向和理由；研究者要"大白话"时，不列公式，直接讲道理。

## 收尾

1. 覆盖"当前位置"，附下一个对话的开场指令。
2. 更新"跨章待办"：新开的加进去，已关的删掉（对应章的"待定"同步删）。
3. 每次回复末尾写三样：
   - 落点表：| 文件 | 节 | 改了什么 |。分析性回答也写明"已写进 X 节"或"未写进文件"。
   - 进展：整体研究进度一句话。
   - 下一步。
4. 改动按轮、可审：一轮一个 diff，研究者审后自己 git 提交。

## 冲刺模式

**什么时候用**：要在几小时内走完多个阶段时。范例：`冲刺_2026-10-03.md`。

1. **倒推**：终点要什么（例：沙盘五块版面要哪些数）→ 每阶段只做终点要的。写明"这轮拿不到的"。
2. **写冲刺文件**：本轮已定（注研究者确认时间）；排期表（时段｜主线｜并行子任务｜研究者）；每个子任务的开场指令。冲刺后并入总计划，冲刺文件留作记录。
3. **开场指令怎么写**：
   - 共用开头：仓库路径；先读冲刺文件、主文件"当前位置"和第 0 章；只做这一件；回复写落点。
   - 共用规矩：数只引用主文件并注节号；同一个数各处写法一致；不换字；没有的数标"判断值"并写理由。
   - 每条四项：本次只做｜它回答什么｜输入（注明以哪个检查点审过的版本为准）｜产出（路径、篇幅上限）。
   - 标准：可以直接粘进新对话重做。
4. **分工**：本对话当主持，做主线、整合；可并行的事交子任务在独立上下文做。主持只看结果、统一口径，不在自己上下文里重做。子任务开写前给一份"写作简报"（关键数、已定事项、全书结论），避免各写各的。
5. **检查点**：设 3–4 个，研究者每个审一次、提交一次。检查点前主持做一致性核对：同一个数各处写法一致、节号对、不碰已定口径；不一致的列清单改齐再交审。检查点上研究者改了口径，先写下改了什么，再让依赖它的子任务开工。
6. **冻结**：已定稿的章不动；冲刺中冒出的新问题一律进跨章待办，冲刺后再看。

## 审稿复核

- **何时**：高风险结论——动"几年几倍"、三档里越过阈值、推翻已定口径。
- **怎么做**：另起一个没看过写作过程的审稿子任务，只给成品和要核的问题，让它查算式、来源、前后自洽和常识，交一份完整清单。不给它主持的推理。
- **外部评审**：研究者拿其他模型的评审回来时，逐条判对、错或部分对并写理由；先与研究者对齐，再一次合并修改，并自查错为什么反复出现。

## 常见的坑

1. **不先定终点就往下抠**：从每格成本往上算，越抠越细收不住。先倒推。
2. **说过的逻辑做时悄悄丢掉**：已定判断要么守，要么明说推翻。
3. **子任务口径不一**：28.9% 和 28.89% 并存、节号引错。检查点前核对。
4. **文档里写工作代号**（如"A6"）：独立读者看不懂，写成大白话。
5. **误跑冻结的旧程序**：旧流水线会覆盖新正文。冻结时在冲刺文件写明"不要再跑"。
6. **三档一起往坏里调**：设备、投资这类不会更差的数也进悲观档，会造出"哪里都不行"的假象；三档只动真会变的数。

# 换电战略决策模型 v4.3

> **换新对话接续工作？按这个顺序读三份：**
> **① [交接.md](./交接.md)**（现在到哪了、下一步）→ **② [框架提案.md](./框架提案.md)**（要造成什么样）
> → **③ [研究项目约定.md](./研究项目约定.md)**（文件怎么放、怎么协作）。
> 想知道某个判断当初怎么改对的，去 [DECISIONS.md](./DECISIONS.md) 查。
>
> **本目录的目标**：让模型的计算结果**自动**变成一份投资人视角的换电分析报告——
> 定量算完 → 触发 LLM 写正文 → 装配成一份可下钻、可交互的长报告。
> 报告要回答的是投资判断（必要性／可行性／对业绩与市值的影响／是否引发重估），
> 不是模型说明书。

## 一、三条命令

平时只需要记这三条。每条都会把失败停在原地并说清楚原因。

```bash
python src/build.py           # ① 全流程：跑模型 → 出事实包 → 检查叙述层 → 注入落盘
python src/tree.py            # ② 链路审计：从决策到参数逐层自校验（三情景）
python src/lab.py workbook    # ③ 参数血缘：生成 Excel 七表（假设／结果／敏感性／双向血缘）
```

想改参数但不写代码：`python src/lab.py workbook` → 在 Excel 改「试算值」→ `lab.py trial`
看对比 → 满意了 `lab.py commit` 落盘 → `build.py` 刷新。全程不碰代码。

## 三、数据流：数字只有一个家

```
configs/base.toml
      │  python src/run.py
      ▼
outputs/decision_snapshot_v4_3.json  ← 唯一事实源
      │
      ├─ report.py ──▶ 骨架报告（机器填数）
      ├─ facts.py  ──▶ facts.json ──┐
      ├─ tree.py   ──▶ tree.json / Excel 树
      └─ lab.py    ──▶ 血缘 Excel     │
                                      │
narrative/*.src.md（人写，只有占位符）─┴─ inject.py ──▶ outputs/*.md
```

**三条纪律，都由程序强制，不靠自觉：**

1. **叙述层不许出现字面数字** —— 只能写 `{{q3.increment}}`。`build.py` 扫到裸数字就中断构建。
   （白名单：年份、章节号、版本号、有序列表序号、`Q1`–`Q4`、代码块、链接目标。）
2. **树的每个内部节点必须自洽** —— `combine(子节点值) == 本节点值`，对不上就在那个节点报错。
   模型改了公式而树没跟上，重跑立刻暴露。
3. **每个叶参数必须有取值依据** —— base.toml 里键上方的注释块或行尾注释，二者认其一。
   缺的会被 `tree.py` 列出来。

### 4.1 敏感性分析怎么做（两个"幅度"最容易搞混）

**分工**：`src/lab.py` 只负责**跑逻辑、量敏感度**；所有**数字**——参数值、情景档位、
不可调名单、微扰幅度——都住在 `configs/base.toml`。所以调参数、改档位一律改 base.toml，
不要动 Python。

|  | ① 微扰幅度 `step` | ② 情景档位（`[drivers]`） |
|---|---|---|
| **在哪设** | `base.toml [sensitivity].step`（默认 0.10） | `base.toml [drivers.xxx]` 的 悲观/中性/乐观 |
| **干什么** | **测量**：把参数轻轻推一下，量它有多敏感——它是**尺子** | **判断**：你认为世界会变成什么样，这条轴该摆多远 |
| **谁定** | 程序默认，一般不用改（`--step 0.2` 可临时换） | **你定** ← 这才需要校准 |

**三种"影响"别拿错表看错数**：

| 表 | 在哪看 | 回答什么 |
|---|---|---|
| 单参数弹性 | `参数与血缘_v4.3.xlsx` → `03_敏感性矩阵` | 单个参数 +10%，各指标变百分之几 |
| 轴级弹性 | `python src/lab.py scan` → 【表 0】 | 一条轴的参数**一起** +10%，增量价值变多少 |
| **轴级实际影响** | `换电模型_参数与血缘_v4.3.xlsx` → `03b_轴级影响` | 这条轴**真的调到乐观/悲观档**时，增量价值/收入/EBITDA 各变多少 |

⚠️ **排序可能不一样**：弹性量的是"每 +10%"的灵敏度，但各轴实际摆幅不同
（如 `commercial_swap_share` 摆 ±30%，而 `commercial_nev_penetration` 只摆 ±15%）。
所以要挑"最该跟踪哪条轴"，看「轴级影响」页签的**实际档位变化**，不要只看弹性排名。

> **一页纸**：`outputs/换电沙盘_v4.3.html` 里的「结论校验 · 一页纸」区块＝唯一出口
> （内容源 `narrative/一页纸.md`，数值与顶部读数同源于 `lab.METRICS`，信源引自 `audit/信源审计台账.md`）。
> `outputs/换电一页纸_v4.3.xlsx` 是**旧存档、已停产**，不要再读。

## 五、设计原则（为什么不这样不行）

0. **一个事实只有一个住址**：状态／过程／产物三分，根目录只放纲领。
   见 `研究项目约定.md`——**它是可以复制到其他研究项目的**。
1. **论证与参数分离**：口径推导住 `口径/`，投资论证住 `narrative/topics/`，
   base.toml 只留"值＋取值依据＋锚点"，避免多处论证漂移。
2. **数字只有一个家**：任何文档都不许手写计算结果，只能引用快照。叙述层用占位符从机制上封死。
3. **拍值 ＋ 运行时校验**：规划能力这类拍值不写第二个静态数，由 `station_capacity()`
   每次运行现算物理上限并硬断言——验证链活在代码里，不是文档里的一句话。
4. **派生量不双写**：外部权益 = 1 − construction_ownership 由代码派生，不落第二处。
5. **一律曲线推算**：寿命、价格从基础参数推导，禁止硬编码派生结果。
6. **对照实验**：一切"换电值多少"都是 A（做）vs B（不做）的总账差，不做单边计算。
7. **树的根是决策，不是车辆**：任何结论都能一路点到参数，中间每层都自校验。

## 六、几个容易踩的坑

- **辅助服务三项不能相加。** 容量补偿是"站建成即可申报"的存在型收益，无条件计入；
  需求响应与调频须实际提供服务才有收益，且争夺同一份可调容量，**全局孰高只计一项**。
  故 `ancillary_yi = 容量补偿 + max(需求响应, 调频)`，两个候选项以 `_candidate_yi` 命名，
  另有 `ancillary_counted_item` 标明本情景实际计入哪一项。三项直接相加会高约 29%。
- **CRF 0.15 不是 WACC 口径。** WACC 7.5% 是"必须收回成本的下限"，CRF 用的是**期望收益率**
  （10–15% 区间中值，隐含要求回报约 12.4%）。用 WACC 反推的 0.1133 去质疑它是比错了对象。
  依据见 base.toml 注释与 v3.2 §1.2.2。
- **`nev_rates` 是年更新流量口径，不是保有量口径。** 引用"电动化率"时必须说明是哪一种。
- **outputs/ 下的 md 是生成物。** 想改叙述正文请改 `narrative/*.src.md`。
- **改参数前先看影响面。** `lab.py scan` 实测的前几位是电池价格、站效率 RTE、项目债务比、
  电池价格平台期结束年、重卡保有与纯电占比——动这几个之前务必先 `lab.py impact`。

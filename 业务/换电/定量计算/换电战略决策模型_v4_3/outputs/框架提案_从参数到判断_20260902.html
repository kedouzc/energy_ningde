01

三处必须先解决的问题

这三处不解决，自动化只会把现有的问题跑得更快、更整齐。第一处会改变报告的核心结论，第二处会决定报告能不能真正回答"必要性"，第三处是自动化本身要治的病。

已定性为 BUG

估值主口径：EV/EBITDA 18× 与 EBIT≈0 之间没有和解

已更新 2026-09-02本条当初判断为"两个口径之间的张力，需要正面论证"。 后来查明：EBIT≈0 根本不是一个需要论证的现象，而是 capex.py 的折旧分子写错了。 原式 initial × (capital_multiplier − residual) / life 把「15 年全周期要花多少钱」的 PV 倍数除以「单代电池寿命」，等于把 15 年要买的 5 代电池压进第一代的 2.94 年里摊完—— 15 年累计折旧 12,752 亿，而名义实际支出只有 5,605 亿，2.28 倍。 修正后：折旧 850.2 → 342.4 亿，EBIT 0.25 → 508.0 亿， 项目净利 −104.3 → +332.6 亿。「换电项目在亏钱」是 bug 的产物，不是事实。 详见 DECISIONS.md 2026-09-02 与 09-02c 两条。下面保留当时的原始记录。

快照里这一组数字是同一门生意的同一年：

EBITDA850.4 亿
折旧850.2 亿
EBIT0.25 亿
项目净利−104.3 亿
企业价值15,307 亿

15,307 亿 = 850.4 × 18。也就是说，运营侧 5,092 亿的归属价值，全部由那个 18 倍撑着——而被乘的 EBITDA，几乎全额要用来补电池更新（模型自己算出的全周期年资本要求是 644.6 亿）。同一个模型里还有一句更克制的话：EBITDA 覆盖倍数 1.48 倍，也就是"比要求的回报好一点，但不多"。

这两句话在讲同一件事，却没有互相校验：覆盖倍数说这是一个刚过线的项目，估值说这是一个 18 倍的网络资产。谁都可能对，但报告必须正面回答"凭什么"，否则这是全篇最容易被一句话打穿的地方——问的人只需要问："你用 EBITDA 的 18 倍估值，那 EV/EBIT 是多少倍？"

已更新建议的方向（DCF 为主、倍数降级为交叉验证、把差额显性化）被后续工作证实且已实施， 但结论数字全变了：现金流支持倍数 6.67× → 5.67×，与 18× 的溢价 2.70× → 3.17×， 押注部分 3,855 → 已更新 09-034,122 亿（原为 4,194 亿， 接入期末残值税后现金流后微降，详见下方②与 DECISIONS.md）。而且发现了一处更要紧的东西—— 覆盖倍数从 1.476× 掉到 1.14×：虚增的折旧原本制造了大额虚假税盾，把门槛 EBITDA 压低了。 第 3 章「经济门」的真实余量只有 14%，不是 48%。

我的建议不是把数字改小，而是换主口径：把项目自由现金流的 DCF 作为主算法（模型里 forward_fcff、required_fcff 已经在算了），EV/EBITDA 降级为交叉验证，并且明确写出"DCF 隐含的倍数是 X 倍，我用 18 倍，差额是我对基础设施网络溢价的判断"。那个差额恰恰就是你要的非共识——把它显性化，比把它藏在乘数里有说服力得多。

改论证

"必要性"要量化，但补"对手做成了"这一支不是解法

已修正初稿在这里提议补一条 C 分支（我不做、对手做成了）。这个提法在本案不成立：换电圈内没有够格的对手——启源芯动力第一大股东已是 CATL，奥动、协鑫等体量不足；快充阵营和换电是错位竞争——华为超充与比亚迪闪充目前主攻私家车，换电的基本盘是营运车。"对手"这个变量定义不出来。C 分支取消。

必要性的真正形态是防守反击：动力电池线的市占与净利率都在被挤压，而 CATL 靠这条线起家，没道理也不应该放弃它——所以它无论如何要打一仗。问题只是从哪里着力。可选的路有三条，按"作用在谁身上"排开，答案就出来了：

着力点性质作用对象对存量盘
固态电池等新技术技术迭代 · 开源新产品弱——新产品救不了老盘，且能支撑到什么程度还不确定
圈矿降本节流成本端提净利率，但不带量
换电新商业打法 · 开源成熟产品锁量 ＋ 护价，两者都落在存量盘上

开源永远比节流重要——成本降得再多，货铺不出去也没用。在新技术还不确定的窗口里，老盘不能丢，就必须在成熟产品上换一种商业打法打出去。换电是三条路里唯一一条既是开源、又直接作用在存量盘上的。这就是必要性，不需要任何假想敌。

模型对这条论证其实已经有数了，只是位置不对：制造侧的锁定订单效应和净利率保护效应正是"锁量"与"护价"，现在藏在估值分解里，该提到第 2 章当主证。

次一级：窗口期

有了上面这条，才轮到问窗口——如果建设期整体往后排，快充那条线会不会把能做换电的窗口彻底挤掉。做法是排期后推重跑，同时下调期间可达的换电渗透率上限（不只是折现晚了，是天花板被压低了）。快充阵营在这里出场，作为窗口的压缩者，而不是必要性的假想敌。

最弱：资金与市值管理，而且要挪位置

"同样的钱去回购只有约 5% 隐含回报"这条比想象中弱：账上近 4,000 亿现金，回购才用了 400 亿，本来就是上市公司做市值管理的常规操作（全球大市值公司普遍如此），并不构成"不做回购就该做换电"的对立。两者目的根本不同——回购是给股价托底，换电是稳业务线，财务回报好只是顺带。

所以这条应该从第 2 章挪到第 3 章可行性的资金门，改成一句财务纪律检验：换电的回报不低于常规资金用途，因此它不需要靠战略理由豁免财务标准。这才是它该干的活。

已发生

同一个结论，三份文档里是三个数

"可归因换电增量价值"这一个指标：

文档数值占市值状态
decision_snapshot（真值）5,698.3 亿28.5%当前
骨架报告 v4.35,698.3 亿28.5%一致
MANIFEST 快速导读6,724.5 亿33.6%已过时
叙述报告 v4.38,026.4 亿40.1%已过时且拆法不同

而且叙述报告把增量拆成三块（运营 + 护价 + 锁量），MANIFEST 和骨架报告拆成两块——不只是数字旧了，口径本身也分了叉。backscan.py 是对的设计，但它只在你想起来的时候跑，而且靠字符串比对，改一次格式就漏一次。

这不是纪律问题，是架构问题：只要叙述层允许出现字面数字，漂移就一定会回来。第 03 节的那条硬规则就是冲着它去的。

2026-09-02 新增

定性与定量在讲两个故事：制造侧净贡献只有 10.6%

已定的必要性论证是"换电作用在存量盘上、锁量＋护价"。但 ledger 实跑分解说的是另一件事：

分项价值（亿）
换电运营自身（18× 撑起）5,091.6
制造侧 · 锁定订单（锁量）+1,075.5
制造侧 · 充电份额流失−1,153.0
制造侧 · 净利率保护（护价）+684.2
制造侧 · 销量份额−77.5
制造侧净贡献合计+606.7（10.6%）

89.4% 的价值来自换电运营网络自身那个最难辩护的 18× 倍数，而必要性论证赖以成立的锁量／护价， 净贡献只有 606.7 亿——锁量 +1,075 几乎被充电份额流失 −1,153 全额抵消（该项是否与锁量重复计提，口径待查）。

解药：把战略溢价从倍数里拿出来，放回它真正落地的地方。 v3.2 §4.1③ 自己写了"payoff 主要落在动力电池基本盘，而非换电自身的现金流与估值"—— 既然如此，就不该把这份 payoff 表达成换电运营线的更高倍数。换电运营用基建区间的诚实倍数 （再投资强度 EAC/EBITDA ≈ 76%，在基建族里属极高，应锚下沿）；战略价值用已有的锁量／护价， 作用在制造侧、用制造侧 PE 计价。每块价值用自己盘子的倍数，"溢价"这个词就不需要了。

顺带一处逻辑缺口：v3.2 §4.1 说"锚 6.7–14× ＋ 温和战略溢价 → 18× 取上限附近的中枢"， 但 18 比区间上限 14 高 29%、比中值 10.35 高 74%，根本不在区间内。"温和"两个字承担了太多。

02

目标报告长什么样

你要的不是"模型结果的说明书"，是一份投资人拿去做五年决策的报告。所以骨架不按模型的层（车辆/站点/运营/财务）走，按决策的问题走——每一章都必须由一个算出来的数来收口，否则那章就是散文。

章回答什么必须由计算收口的东西模型现状
0 决策卡买不买、赔率多少、时间窗多长、什么会证伪三情景下的 5 年回报区间 + 证伪阈值清单需新增
1 非共识在哪控制参量（真实投入）已经走了多远，序参量（市场定价框架）还没动多少共识锚：卖方一致预期 EPS / PE，与我的预测的差需新增
2 必要性动力线在缩水，防守反击从哪里着力——为什么是换电，不是固态、不是矿换电锁住多少 GWh、护住多少净利率；晚做两年天花板压低多少锁量护价模型已有，需提到主证位置；窗口成本需新增
3 可行性四道门：物理能不能建、经济能不能过线、钱够不够、车企配不配合门槛清单，每道门一个通过/不通过 + 余量物理与资金已有，经济与博弈缺
4 业绩影响 方法论待定 09-032026–2031 逐年，对合并报表的收入/净利/EPS 贡献多少年度化的并表贡献表（含权益法与并表口径差异）只有 2030 单点；是否该做成"逐年精算"还是"终局+爬坡毛估估"，与"算细读粗"方法论主线有张力，讨论中，见下方 08 节
5 市值与重估ΔE（利润变多少）× Δ倍数（框架换不换）的二维分解重估触发条件 + 隐含倍数与 DCF 倍数的差需新增
6 五年判断赔率表、催化剂日历、中检点、退出信号先行指标与验证指标的收敛度V3.0 报告有指标库，未接模型
7 诚实清单这套测算最可能错在哪，错了影响多大弹性排名前 10 的参数 + 各自的翻盘阈值lab.py scan 已有

为什么这个骨架比参考文件（1）（2）（3）更好

重构版和 V3.0 的定性很强，但它们的定量是附在结尾的一章；v3.2 折扣链的定量很细，但它的定性是"为什么这么算"而不是"这值不值得买"。两边都缺同一样东西：把定性结论翻译成一个可以证伪的数，再把这个数放回决策里。

上面这张表的每一行，右边那列都是一把锁。0 章的赔率区间锁住"值不值得"，2 章的 B−C 锁住"必要性"，3 章的门槛清单锁住"可行性"，5 章的倍数差锁住"重估"。定性负责论证锁该锁在哪，定量负责给出锁的读数。这也是为什么第 01 节那两处必须先改——没有 C 分支，第 2 章只能继续写断言；没有 DCF 主口径，第 5 章的重估就是自我循环（用倍数论证倍数）。

关于"非共识"这个主题

你的投资主题是非共识机会，那么报告里必须有一个地方是可以和市场逐条对账的：市场现在的 2030 年 EPS 预期是多少、给多少倍、隐含了换电贡献几乎为零——这三句话都要有出处。没有这个锚，"非共识"就只是我方的自述。这就是第 1 章"共识锚"要新增的原因，它是整篇报告里唯一一个必须从外部（卖方一致预期）取的数。

03

流水线架构：四层 + 一条硬规则

你的直觉是对的——HTML 只做组装、逻辑住在 MD、计算住在程序。下面把这个直觉补成一条能自动跑通的链，关键在中间多一层"事实包"，以及一条听起来极端但能一劳永逸的规则。

L0 参数base.toml212 个参数，每个带一行理由和锚点。人改的只有这里。已有
L1 计算src/ + chain_tablePython 唯一引擎。产出快照与全链条表。已有 · 需补 C 分支 / DCF / 年度化
L2 事实包facts.json给叙述层用的命名事实字典。每条自带取值路径、单位、格式、复核阈值。新增（核心）
L3 叙述章节 MD七章正文。只写论证与判断，数字一律写占位符。LLM 起草 · 你终审
L4 装配report.html替换占位符、渲染 MD、挂交互沙盘。不含任何业务文字与公式。薄容器
硬规则叙述层的 MD 里不允许出现任何字面数字（年份等白名单除外）。所有数字只能写成 {{val.total_increment}} 这样的占位符，由装配时从事实包注入。

为什么这条规则值得那么硬

现在的 backscan.py 是"写完之后去查有没有对上"，属于事后抽检——所以会有 6,724 和 8,026 这两个漏网的。改成占位符之后，检查从"字符串比对"变成"文件里还有没有裸数字"，这是一个正则就能穷尽的检查，不可能漏。副作用更重要：改一个参数重跑，叙述报告里所有数字自动更新，不需要 LLM 重写一遍，也不需要你重读一遍。

事实包长这样

字段作用例
from快照里的取值路径。数字永远不是手打的ledger.total_swap_increment_value_yi
v / unit / fmt值、单位、格式化方式（千分位与小数位统一在这里定）5698.3 / 亿元 / #,##0.0
watch复核阈值。重跑后变动超过它，引用它的段落自动标"待复核"0.05
gate若是门槛类事实，写判定条件，装配时渲染成通过/不通过的标记>= 1.0
src信源。直接从 base.toml 注释和信源审计台账继承§4.2.4 三路径核验

增量重生成：数字自动更新，判断需要复核

每段叙述记录它引用了哪些占位符。重跑之后：占位符变了但都在 watch 阈值内 → 静默更新；有占位符越了阈值，或者某道门的通过/不通过翻转了 → 这一段被标成待复核，交给 LLM 只重写这一段，你只看被标记的段落。这解决了"改一个参数要重读全文"的问题，也是"全流程自动化"里最难但最值钱的一环。

一条命令

python src/build.py 依次做：跑模型 → 出快照 → 出全链条表 → 生成事实包 → 校验叙述层无裸数字 → 检查待复核段落 → 注入并渲染 HTML。任何一步失败就停在那里并说清哪一步、为什么。你平时只需要记这一条命令。

04

MANIFEST 为什么难读，怎么拆

"语言太僵化、看不懂、调起来费劲"不是文笔问题。根因是这一份文档同时在服务三个完全不同的读者，被迫用一种谁都不舒服的语言写。

现在混在一起的三件事读者天然的语言拆到哪里
论点：为什么必做、为什么这么判断你和读报告的人你自己的话，有主张有取舍叙述层七章 MD（第 02 节）
口径：每个参数怎么取的、信源是什么核查的人（也是未来的你）台账体，机器感是对的base.toml 注释 + 信源审计台账（已有，保持）
链路：这个数由哪些数算出来想追一个数的人不该是文字，该是表chain_table 的输出

第三件事是关键。用散文描述算术，一定会写成你现在看到的那种句子——"终局装机由车辆数乘装车电量再加站内周转推得，其中站内周转由……"。这种句子写起来累、读起来更累、改一个口径要重写一整段。chain_table.py 的方向完全正确，但它现在还没做到你想要的那件事。

chain_table 为什么还不是"以终为始"

我把行定义逐段读了一遍。三处是结构性的，不是 bug：

问题现在是怎样后果
根节点不是决策整表按 A 车辆 → B 运营 → C 站数 → D 电池 CAPEX → E 收入成本 → F 估值 排列；A 段的根是"换电车辆（万辆）"这是模型的计算顺序（自底向上），不是决策的分解顺序。真正的以终为始，根该是"这笔投资值不值得做"，往下才轮到车辆
树是假的层级靠 ↳ / ↳↳ / ↳↳↳ 字符串前缀表示，底层是一个扁平行列表不能折叠、不能从任意节点下钻、更关键——没法做"父＝f(子)"的递归校验
公式与代码只是弱绑定公式列是手写中文，靠每行一个可选的 check lambda 兜底配了 check 的行会报错，没配的静默错下去——这大概就是"错误挺多"的来源

值得保留的两个设计

  • 公式与数值分离：数值一律模型实跑，公式只写中文名运算、绝不写具体数字。这条纪律是对的，继续用。
  • 自校验的思路：公式和模型对不上就当场报错，比写注释可靠得多。要保留，但从"每行一个"升级成"每个节点递归"。

重建成什么样

把树声明成递归节点，而不是带前缀的行。每个非叶节点带一个可执行的 combine，程序拿子节点的值算一遍，和模型实跑的值比对——对不上就在那个节点当场失败，并指出是哪一层断的。叶节点就是 base.toml 里的参数，挂信源和实测弹性。

不变量对树里每一个非叶节点：combine(子节点值) == 模型实跑值。这一条成立，树才是"活的"——模型改了公式而树没跟上，重跑会当场失败，而不是悄悄给出一张错表。

产出是一份递归的 tree.json（每节点带 值／公式／单位／信源／弹性／子节点），三个地方消费它：报告正文的下钻、HTML 沙盘、Excel 导出。验收标准很具体——从"换电值不值得做"点三下能点到 base.toml 里的某一个参数，中间每一步都有公式、值、信源和弹性。

MANIFEST 则瘦身成一份两页的地图（这个模型回答什么问题、分几层、每层的口径入口在哪），原来第 2 到第 6 章那些描述算术的段落，全部由树接管。

交互沙盘：把"可行性验证"从单站升到集团

你在 model.html 里做的那个"第一步敏感性分析 / 第二步自动优化"是整个仓库里交互设计最好的部分——它不是让人乱拖滑块，而是先给目标，再问要调什么才够得着。这个模式应该原样搬到新报告，但对象从单站 IRR 换成集团层面的四个结论。

沙盘的三个动作

  1. 勾选调整项：不是 212 个参数全给。只给弹性实测排名前 12 的（电池价格、重卡保有与纯电占比、价格平台期结束年、服务费、换电渗透率、估值倍数、WACC……），每个带一行"它为什么重要"和当前信源。

关于五年期

你问有没有更合理的建议。我的答案是：五年在这个案子上是对的，但你现在给的理由（太短看不清、太长也看不清）撑不住它——换个理由，它会硬很多，而且能顺便给出中途的判断点。

已更新 2026-09-02本节当初把"十五五规划周期"当作五年期的主要理由。 后来纠正：主因不是规划周期，是竞争格局倒逼的硬死线。正确的因果是—— 竞争格局激烈（与华为、比亚迪角逐补能路线）→ 倒逼 2028 必须建成 → 建成后爬坡两年 → 2030 第一次能观察到成熟期读数。十五五口径（权威预测节点落在 2030/2035）是佐证，不是主因。 另需澄清：曾一度把"2030 可发 REITs、形成投入—回收闭环"当成终局理由，这也不对—— 发不发 REITs 只是 CATL 的一个选择，那是「能力」不是「目的」， 它降级为第 5 章桶③「现金流合同化」的一个可选验证指标：发了是强证据，不发不证伪。 「2028 的紧迫性」则提到第 2 章必要性的窗口期一节，与"快充会不会挤掉窗口"合并。

口径佐证：十五五 2026–2030，模型算到 2030

已修正初稿建议把测算延到 2031（今天＋五年）。更好的锚是十五五规划周期本身：2026–2030 含首尾正好五年。三个理由——公开权威预测的节点普遍落在 2030/2035，做 2031 要插值、平白引入误差；企业按五年规划配资源，序参量翻转大概率在规划周期末被确认；模型终局年本来就是 2030，不必改动。五年因此不是"今天＋5"这个任意整数，而是一个真实存在的周期。

另外两个理由仍然成立，而且和十五五这个锚咬得更紧：

一，这正好是这门生意跑完一个完整资产周转的时间。四个电池池的寿命是 2–5 年，站网 2030 达峰。要到 2030 年前后，才第一次能观察到"建站 → 运营 → 电池到期更换 → 残值回收"这个闭环的真实读数。在那之前，任何"复利生意"的说法都还是推演。

二，它覆盖了序参量翻转的窗口。控制参量（资本开支、时代电服、团队）已经在动，序参量（市场用制造业还是运营业给它定价）还卡着。翻转要等验证指标兑现——多城盈利、时代电服独立融资、券商开始单独给换电估值。不可逆点在 2028、站网达峰在 2030。

重估兑现那一年怎么处理

不进模型。模型只负责控制参量（业绩算到 2030），序参量（倍数）用情景表达——重估是市场行为，不是能预测出来的经营数据。第 5 章把它写成"倍数从阶梯的哪一档走到哪一档"，第 6 章把它写成退出信号。这样业绩和重估两件事干净分开，正好对应控制参量与序参量的区分，也省掉了 2031 那一年的插值。

持有期不是一段无差别的等待，报告输出三个刻度：

沉淀成什么：三个 skill，一个红队

你问要不要沉淀成 skill 和 agent。我的看法是：skill 要，九个 agent 不要——至少现在不要。

你在《研究思考链路》里拆的九个模块（场解码器、需求识别器、业绩测算器……）作为概念地图是清楚的，但作为运行架构会放大你现在正难受的那个毛病。每个 agent 冷启动、各自重新推一遍上下文、交接处产生接缝——你现在感觉到的"割裂感"，正是模块之间交接留下的痕迹。九个 agent 会把这些接缝制度化。

skill 不一样。skill 是一个 agent 在正确的时刻读到的一份检查表和提问链，不产生交接，也不丢上下文。你要沉淀的东西——客观大场定位诊断那四步、相变六步、四条铁律、参数信源绑定纪律——本质上全是"提问的顺序"和"不许做的事"，正好是 skill 这个容器最擅长装的。

skill装什么迁移时改什么
非共识标的诊断入口层：PBL 五问 → 人物校验 → 客观大场定位四步诊断 → 相变六步（买前 4 步 / 买后 2 步）。产出"值不值得研究 / 非共识在哪 / 窗口多大"。几乎不改。这一层是 domain-general 的——换成研究一家餐饮连锁也能用
反事实定量建模A/B/C 三分支设计、分母必须外部独立、参数与信源绑定、门槛清单、弹性实测法、快照单一事实源。附一份可复制的工程骨架（config / engine / snapshot / chain_table / facts / backscan）。改"载体本质"和四类客户的拆法；骨架不改
研报装配七章骨架、占位符纪律、事实包结构、待复核机制、HTML 薄容器与高亮标注规范（沿用你已写好的 HTML-MD 映射范式）。不改

唯一值得单独开一个 subagent 的角色：反方审稿

读完成稿 + 快照，专门找刀口：EV/EBITDA 与 EBIT 打不打架、乘数有没有循环论证、四层增量有没有重复计算、分母是不是在自证、哪个结论其实只靠一个未核验的经验假设撑着。这是唯一一个"冷启动、没有上下文"反而是优势的角色——因为它要模拟的就是一个不了解你思路的怀疑者。第 01 节那三处发现，就是这个角色跑出来的东西。

泛化的边界，值得先写进 skill 里

"电池和芯片底层都是电子有序流动"这个同构，物理层是硬的；但由它推出的"信息侧集中、能量侧标准化"是经济学结论，不是物理结论——它真正的依据是复制的边际成本，而不是电子。所以泛化时要分层给置信度：方法论（回到载体本质 → 识别真需求 → 反事实增量 → 参数信源绑定）几乎不需要这个前提就能迁移；需要这个前提的，只有那条具体的经验规律。把这句话写进 skill 的开头，可以防止未来某次泛化时把它当公理用。

议题结论
第 5 章怎么处理那 3.17 倍溢价四桶分解 ＋ 双峰赔率（取代原甲／乙／丙）。为什么付 18× 而不是 5.67×，只可能是四件事之一：① 预测期外还在长（新品类被验证）；② 基准外期权（V2G／储能／数据／REITs）；③ 风险低于 WACC 假设（现金流合同化）；④ 纯重估押注。只有 ④ 是赌，而"新品类／马太效应／垄断性"这些论据其实属于 ①②③——把它们挪过去，论点就从"信念"变成"可以算的东西"。
双峰赔率：倍数不会平滑漂移，它贴着制造业锚不动直到跳变，所以不报期望值，报四行——世界 A（未相变）＝地板／世界 B（相变）＝天花板／从 A 到 B 要看到什么／今天价格离 A 多远＝亏损上限。
非共识 vs 自欺的判据你的论点必须能被市场之外的东西证伪。若论点是"市场会给 18 倍"，唯一的证伪方式就是市场不给——要等 5 年，期间没有任何中间信息，那不是非共识，是不可证伪的信仰。若论点是"这门生意会跑出 A／B／C 三个特征，而具备这三个特征的资产历史上都拿到十几倍"，A／B／C 每一个都能在 2027–2028 单独观察。非共识是「你比市场早看到 A、B、C」，不是「你比市场更相信 18 这个数字」。而且 2028 就知道输赢，不用等到 2030。
"特征"与既有框架的挂接四桶里 ①②③ 的"特征"就是共振框架里的先行指标（②的 V2G／储能接入容量、③的长约占比与 REITs／ABS 发行、①的营运车渗透 S 曲线）；桶④没有先行指标——这正是它是赌的原因。"先行指标与验证指标的收敛度"作为退出信号，至此有了具体挂载点。
带爬坡的逐年 DCF 出来后倍数会更低仍然成立且方向不变：现在两条口径都用成熟期 FCFF 资本化、未扣建设期爬坡，都偏乐观。年度化做完后以逐年 DCF 为准，成熟期口径降为附录对照。
建模粒度（毛估估 vs 精算）精度 ≠ 假设数量：区别不在程序算多少步，而在你要拍多少个数。电池价格路径由 5 个参数生成 20 年的价格——逐年算新增假设数为 0。定为让程序算细、让报告读粗，中间明细是可下钻的证据不是要读的内容；标定一次、用很多次（实测：全部批次按一个标准年处理，代价仅 0.9%，而服务费不确定度是 ±33%）。标准年取 2026＝决策时点＝估值基年。

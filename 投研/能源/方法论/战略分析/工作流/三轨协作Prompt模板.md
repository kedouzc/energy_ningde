# 三轨协作Prompt模板

> **来源**：从《战略决策投研框架及AI协作痛点诊断优化方案.md》步骤3提取整理。
> **用途**：8步工作流每一步的关键判断节点，均可使用三轨协作机制。
> **原则**：蓝队建设、红队攻击、影子轨提炼；裁判翻译红队攻击，蓝队只接收修正指令。

---

## 一、三轨协作机制总览

```
                    ┌─────────────────────────────────────────────────┐
                    │                   你（裁判）                     │
                    │  ① 从蓝队输出中提取关键判断节点                   │
                    │  ② 判断该节点是否值得红队攻击（不是每个都要）      │
                    │  ③ 将红队攻击翻译为"修正指令"                    │
                    │  ④ 决定是否触发影子轨                           │
                    └─────────────────────────┬───────────────────────┘
                                              │
                      ┌───────────────────────┼───────────────────────┐
                      │                       │                       │
                      ▼                       ▼                       ▼
              ┌───────────────┐       ┌───────────────┐       ┌───────────────┐
              │  蓝队 Agent A │       │  红队 Agent B │       │ 影子轨 Agent C│
              │  (建设者)      │       │  (毁灭者)      │       │  (提炼者)      │
              ├───────────────┤       ├───────────────┤       ├───────────────┤
              │ 任务：推演     │       │ 任务：攻击     │       │ 任务：脱水     │
              │ 输出：结构化   │       │ 输出：漏洞清单 │       │ 输出：模板骨架 │
              │ 论证          │       │               │       │               │
              └───────────────┘       └───────────────┘       └───────────────┘
```

### 信息流动规则

- **蓝队产出**：①结构化分析 ②对应问题链的哪一环 ③对最终决策的价值
- **红队产出**：①反方论据 ②对应问题链的哪一环 ③对最终决策的价值
- **影子轨产出**：①分析模板骨架 ②对应问题链的哪一环 ③对最终决策的价值

### 关键原则

1. 每次只推进一个环节；
2. 不要让AI"推荐下一个问题"——问题链由你掌控；
3. 判断权永远在你手里，AI只负责提供结构化的判断素材；
4. 异构多模型对抗做批判：**红队报告永不直接输入蓝队**。蓝队只接收你翻译后的"修正指令"，不接收红队原文；
5. 异步双轨制提炼方法论：影子轨仅仅在关键判断节点完成后触发。

### 关键判断节点的判定标准

- 这个判断是后续推导的前提（如"7个需求清单"）
- 这个判断涉及逻辑跃迁（如"从需求到战略方向"）
- 这个判断涉及取舍（如"选择A放弃B的理由"）

## 二、蓝队Prompt模板

### 2.1 初始版（收到红队攻击前）

```
【角色】你是投研分析师（蓝队），服务于投资决策团队。

【任务】按指定的问题链环节，完成结构化分析。

【分析主题】：当前回答的问题链第X环——[环名]

【上游输入】：
[粘贴上一步传递的输入包]

【AI执行五条军规】：
1. 单一目标校验：所有输出必须最终服务于[本次分析的核心目标]
2. 刚性约束优先级：[现金流约束＞能力约束＞行业趋势＞政策约束]
3. 层级锁死：当前层级未完成时，禁止跳转下一层级
4. 问题收敛规则：每个问题/检索请求必须标注"对应问题链哪一环+对最终决策的价值"
5. 正反方强制输出：每个结论必须同时输出正方论据和反方论据

【输出格式】：
【分析主题】：当前回答的问题链第X环

【信息摘要】：
- 关键事实1（来源，置信度：高/中/低）
- 关键事实2（来源，置信度：高/中/低）
- ……

【因果链】：从事实到结论的推导路径
事实A → 推论B → 结论C（标注每一步的关键假设）

【论据】：支持结论的逻辑链
- 论据1（关键假设，置信度：高/中/低，适用范围：全场景/特定场景）
- 论据2

【正反方对照】：
| 维度 | 正方论据 | 反方论据 | 裁判需裁定 |
|:---|:---|:---|:---|
| [维度] | [支持结论的论据] | [反对结论的论据] | [需要用户判断的点] |

【本环节结论】：本次分析是否足以支撑判断
- 若足以支撑：明确结论是什么
- 若不足以支撑：缺口是什么（信息缺口/逻辑缺口/假设缺口）

【对用户的请求】：需要用户做出哪些判断或选择
- 例如："请裁定：正方论据1和反方论据1，哪个更符合当前行业实际情况？"
- 例如："请确认：因果链中标注的关键假设X，在你的判断中是否成立？"
```

### 2.2 修正版（收到红队攻击后）

```
【角色】你是投研分析师（蓝队），已收到裁判翻译的红队修正指令。

【任务】基于修正指令，更新你的结构化分析。

【分析主题】：当前回答的问题链第X环（红队反馈后修正版）

【修正说明】：基于裁判翻译的红队修正指令，对以下内容做出调整

【信息摘要】：（更新后的信息摘要，标注哪些是新补充的）
- 关键事实1（来源，置信度：高/中/低）
- 关键事实2（来源，置信度：高/中/低）
- [新增] 关键事实3（来源，置信度：高/中/低）

【因果链】：（更新后的推导路径）
事实A → 推论B → 结论C（标注每一步的关键假设）
[修正点] 原假设X被替换为假设Y，理由：...

【论据】：（更新后的论据）
- 论据1（关键假设，置信度：高/中/低，适用范围：全场景/特定场景）
- [新增] 论据2（关键假设，置信度：高/中/低，适用范围：全场景/特定场景）

【对红队攻击的回应】：
- 红队攻击A：已通过[修正点]解决 / 部分解决 / 无法解决（理由）
- 红队攻击B：已通过[修正点]解决 / 部分解决 / 无法解决（理由）

【正反方对照】：（更新后）
| 维度 | 正方论据 | 反方论据 | 裁判需裁定 |
|:---|:---|:---|:---|
| [维度] | [更新后] | [更新后] | [更新后] |

【本环节修正后结论】：是否仍支撑原判断
- 支撑原判断：结论不变，论据已加固
- 部分支撑：原判断被削弱，调整后的判断是...
- 不支撑：原判断被推翻，新的判断是...

【对用户的请求】：需要用户做出哪些判断或选择
```

## 三、红队Prompt模板

```
【角色】你是一家激进做空机构的首席调查员（红队）。

【你的唯一任务】：无情地摧毁我接下来发给你的这份商业论证。

【要求】：
1. 找出所有违背商业常识的假设、自相矛盾的逻辑跳跃、以及数据支撑不足的断言；
2. 特别关注：这个论证中哪些环节最脆弱？如果我要证伪它，从哪里下手最致命？
3. 你可以独立检索信息，找出被蓝队忽略或低估的关键信息；
4. 如果能证明这份论证不成立，你赢了。

【待攻击的蓝队论证】：
[粘贴蓝队输出]

【输出格式】：

【红队新挖掘信息】：
红队独立检索到的、被蓝队忽略或低估的信息
- 信息1（来源，置信度：高/中/低）
- 信息2（来源，置信度：高/中/低）

【红队论据】：反对结论的逻辑链
- 论据1（关键假设，置信度：高/中/低，适用范围：全场景/特定场景）
- 论据2（关键假设，置信度：高/中/低，适用范围：全场景/特定场景）

【红队结论】：
论证最脆弱的环节（按致命程度排序）：
- 🔴 致命缺陷（可证伪整体论证）：
    环节描述（为什么致命）
- 🟡 严重漏洞（削弱结论但不足以推翻）：
    环节描述（为什么严重）
- 🟢 一般性问题（可修正，不影响整体结论）：
    环节描述（为什么需要修正）

【最关键的攻击点】：
如果只能用一句话证伪这份论证，从哪个点进攻？

【对裁判的请求】：
需要裁判确认哪些假设是否成立，才能决定攻击是否有效
```

## 四、红队攻击翻译Prompt

> **用途**：裁判收到红队攻击后，用此prompt让AI帮你做初稿翻译，然后你来审阅和调整。

```
【角色】你是投研翻译官，负责将红队攻击翻译为蓝队的修正指令。

【任务】我收到了一份红队攻击报告，需要将其中有效的攻击点翻译为蓝队的修正指令。

【翻译三原则】：
1. 从否定转建设性：红队说"这不对"→翻译为"怎么做能对"
2. 从攻击转追问：红队说"假设脆弱"→翻译为"假设成立需要哪些条件"
3. 从结论转路径：红队说"论证不成立"→翻译为"替代论证路径是什么"

【蓝队原始论证】：
[粘贴蓝队输出]

【红队攻击报告】：
[粘贴红队输出]

【你的任务】：
1. 筛选红队攻击中哪些是有效的（不是所有攻击都有效）
2. 将有效的攻击按以上三原则翻译为蓝队的修正指令
3. 输出格式：
   - 【有效攻击1】：红队说... → 翻译为修正指令...
   - 【有效攻击2】：红队说... → 翻译为修正指令...
   - 【无效攻击（忽略）】：红队说... → 忽略理由...
```

## 五、影子轨Prompt模板

```
【角色】你是一位战略方法论提炼专家（影子轨）。

【任务】我会给你一组已经完成红队攻击并修正后的论证材料，请提炼出可泛化的分析模板。

【输入材料】：
- 【蓝队原始论证】：建设方的结构化推演
  [粘贴蓝队原始输出]

- 【红队有效攻击摘要】：经裁判筛选后的红队攻击要点
  [粘贴裁判筛选后的红队攻击要点]

- 【蓝队修正后结论】：蓝队根据修正指令修改后的最终版本
  [粘贴蓝队修正后输出]

【你的任务】：

任务一：提炼蓝队的思维模式
1. 思维模型：蓝队分析这类问题时用了什么逻辑框架？
   （例如：从不变性出发→推导刚需→筛选长坡厚雪→匹配业务形态）
2. 决策树框架：做判断需要依次回答哪些问题？问题之间的先后依赖关系是什么？
3. 信息需求模式：蓝队在每一步依赖什么类型的信息？
   （政策文件/行业数据/竞争格局/财务模型等）

任务二：提炼红队的思维模式
1. 攻击模型：红队从哪些角度切入攻击？
   （假设脆弱性/逻辑跳跃/数据支撑不足/可行性约束等）
2. 红队攻击的有效性判断：什么样的攻击是致命的？什么样的是噪音？

任务三：输出通用分析模板骨架
剥离所有具体业务名词（电池、换电、宁德时代、车企），保留可迁移的分析框架：

【分析模板骨架】：

一、问题类型
[归因分析 / 趋势判断 / 可行性评估 / 风险识别 / 取舍决策]

二、核心逻辑链条（通用推导路径）
问题 → 需要回答的子问题1 → 需要回答的子问题2 → ... → 判断标准 → 可能的结论

三、所需信息类别
- 信息类型1（为什么需要，在哪个环节使用）
- 信息类型2（为什么需要，在哪个环节使用）

四、关键假设与替代路径
- 假设1（如果不成立，如何修正或替代）
- 假设2（如果不成立，如何修正或替代）

五、判断标准
什么条件下得出结论A，什么条件下得出结论B

六、可迁移场景
- 场景1：为什么适用
- 场景2：为什么适用

七、与已有模板的关系
- 这是新模板 / 对模板X的补充 / 对模板X的修正
```

## 六、三轨协作执行流程

### 6.1 标准执行循环

```
1. 裁判选择问题链的一个环节
   ↓
2. 蓝队执行（用蓝队初始Prompt）→ 输出结构化论证
   ↓
3. 裁判验收蓝队输出
   ├── 输出质量不足 → 要求蓝队重做（同一Prompt）
   └── 输出质量达标 → 判断是否触发红队
        ├── 不需要红队 → 直接写入报告 → 回到步骤1
        └── 需要红队 → 进入步骤4
   ↓
4. 红队攻击（用红队Prompt，独立窗口空上下文）
   ↓
5. 裁判审阅红队攻击
   ├── 攻击无效 → 蓝队结论维持原判 → 写入报告 → 回到步骤1
   └── 攻击有效 → 进入步骤6
   ↓
6. 裁判翻译红队攻击（用红队攻击翻译Prompt）
   → 输出修正指令
   ↓
7. 蓝队修正（用蓝队修正版Prompt + 修正指令）
   → 输出修正后论证
   ↓
8. 裁判验收修正后论证
   ├── 仍不满意 → 可再次触发红队（回到步骤4）
   └── 达标 → 写入报告
   ↓
9. 判断是否触发影子轨
   ├── 判定为关键判断节点 → 触发影子轨 → 输出分析模板骨架
   └── 非关键节点 → 跳过
   ↓
10. 回到步骤1，推进下一个环节
```

### 6.2 触发红队的判断标准

| 场景 | 是否触发红队 | 理由 |
|:---|:---|:---|
| 蓝队结论涉及核心战略判断 | ✅ 触发 | 核心判断必须经受攻击检验 |
| 蓝队结论涉及因果跃迁 | ✅ 触发 | 逻辑跳跃处最脆弱 |
| 蓝队结论涉及取舍决策 | ✅ 触发 | 取舍意味着放弃，需检验放弃的理由 |
| 蓝队结论仅为事实陈述 | ❌ 不触发 | 事实查证即可，不需攻击 |
| 蓝队结论仅为信息汇总 | ❌ 不触发 | 汇总不涉及判断，不需攻击 |

### 6.3 触发影子轨的判断标准

| 场景 | 是否触发影子轨 | 理由 |
|:---|:---|:---|
| 判断是后续推导的前提 | ✅ 触发 | 前提性判断值得提炼模板 |
| 判断涉及逻辑跃迁 | ✅ 触发 | 跃迁逻辑可迁移 |
| 判断涉及取舍 | ✅ 触发 | 取舍逻辑可迁移 |
| 判断仅为事实查证 | ❌ 不触发 | 事实不可迁移 |
| 判断仅为单次性操作 | ❌ 不触发 | 无泛化价值 |

# 《宁德时代换电重估报告》架构设计 + Agent 化工作链条

> 2026-08-23 · 本文是报告的**装配规范 + Agent 化施工图**。它定义：报告由哪些模块组成、每个模块由哪个 Agent 产出、如何自动组装、数据如何流转。
>
> 核心回答：**这份报告目前是手动写的，但每个模块都能由一个专职 Agent 产出，并由一个"装配 Agent"自动组装成完整报告。**

---

## 〇、结论先行：Agent 化是完全可行的，且已经具备架构基础

这份报告天然是"模块化 + 数据驱动"的，正好符合 Agent 分工的要求。关键洞察：

> **报告 = 定性 MD（Agent 写）+ 定量配置（Agent 填参数）+ 计算引擎（固定逻辑）+ HTML 容器（固定交互）+ token 注入（自动组装）。**

其中：
- **定性 MD** → 由"内容 Agent"产出（读研究素材，写六章正文）；
- **定量参数 config.js** → 由"参数 Agent"产出（读外部信源，填参数 + 标信源）；
- **计算引擎 engine.js** → **固定逻辑，不需要 Agent 写**（数学公式不变，只读参数）；
- **HTML 容器** → **固定模板，不需要 Agent 写**（交互逻辑不变）；
- **token 注入** → 由"装配 Agent"自动执行（engine 算 → 替换 `{{TOKEN}}` → 渲染）。

### 关键分离原则（对齐财务模型架构设计 §2）

| 文件 | 性质 | 谁产出 | 改动频率 |
|---|---|---|---|
| HTML 容器 | 固定模板（交互 + 组装） | 人工一次 / Agent 不碰 | 极低 |
| config.js | 纯参数（数据 + 信源） | **参数 Agent** | 高（随数据更新） |
| engine.js | 纯逻辑（数学公式） | 人工一次 / Agent 不碰 | 极低 |
| 子 MD | 纯内容（论述 + 表格） | **内容 Agent** | 中（随研究推进） |

## 二、Agent 工作链条（从研究到报告全流程）

### 2.1 五个 Agent 的分工

| Agent | 职责 | 输入 | 输出 | 对应产出物 |
|---|---|---|---|---|
| **① 研究 Agent** | 读原始素材、提炼结论 | 研究素材（素材-电池装机量.md、终局研究.md、财务模型等） | 结构化结论 + 参数建议 | （上游，不直接产出报告文件） |
| **② 参数 Agent** | 把结论翻译成可计算参数 + 标信源 | 研究 Agent 的结论 + 外部信源 | config.js | 换电重估_config.js |
| **③ 内容 Agent** | 写定性章节正文 | 研究 Agent 的结论 + 六章大纲 | 六章子 MD | 换电重估_子MD/*.md |
| **④ 校验 Agent** | 核对数字一致性、信源可验证、无硬编码 | config.js + 子 MD + 外部信源 | 校验报告 | （质检关卡） |
| **⑤ 装配 Agent** | 组装 + 注入计算结果 | config.js + engine.js + 子 MD + HTML 模板 | 完整报告 | 换电重估报告.html（运行时组装） |

### 2.2 数据流（谁喂给谁）

```
研究素材（原始数据）
   │
   ▼
① 研究 Agent ──► 提炼结论 + 参数建议
   │                    │
   │                    ▼
   │            ② 参数 Agent ──► config.js（参数+信源）
   │                    │
   ▼                    ▼
③ 内容 Agent ──► 六章子MD（含 {{TOKEN}} 占位符）
   │                    │
   └────────┬───────────┘
            ▼
   ④ 校验 Agent（数字一致性 / 信源可验证 / 无硬编码）
            │
            ▼
   ⑤ 装配 Agent（运行时：engine(config) 算 → 替换 {{TOKEN}} → 渲染到 HTML）
            │
            ▼
   完整报告（用户看到）
```

## 三、关键的 Agent 化机制：token 占位符 + 参数信源绑定

### 3.1 token 占位符（内容与计算解耦）

这是**内容 Agent 和参数 Agent 能并行工作、且数字永不硬编码**的关键机制：

- **内容 Agent** 写第六章时，不写具体数字，写 `{{TOTAL_NI}}`、`{{L1}}`、`{{DELTA_VALUE}}` 等占位符；
- **参数 Agent** 填 config.js 的参数值；
- **装配 Agent** 运行时：`engine(config)` 算出结果 → 替换 `{{TOKEN}}` → 渲染。

**好处**：
1. 参数变了，正文数字自动变，无需内容 Agent 重写；
2. 内容 Agent 不需要知道计算细节，只需知道"这里有 {{TOKEN}}"；
3. 数字永不硬编码，从根上避免"第五章逐年抵消硬编码"这类错误。

### 3.2 参数信源绑定（每个参数必须标信源）

config.js 里每个参数带 `source` 字段，三档：

| source 值 | 含义 | 校验 Agent 的动作 |
|---|---|---|
| `外部信源` | 来自年报/半年报/政策/券商 | 检查正文是否有可点击链接 |
| `经验假设` | 非外部信源 | 检查是否明确标注"经验假设"，且不冒充事实 |
| `沿用v2.4` | 沿用毛估估 v2.4 | 检查 v2.4 原文是否存在该值 |

**这是"分母必须来自外部独立信源"纪律的落地机制**——校验 Agent 会重点检查：装车规模（fleetWan）、单车电量、频次等"分母"是否标了 `外部信源`，而不是 `经验假设`。

## 四、各 Agent 的输入输出规范（可执行版）

### 4.1 参数 Agent 的输出规范（config.js 模板）

```javascript
// 每个参数必须是 { value, unit?, source } 结构
var fleetWan = {
  重卡: { value: 38, unit: '万辆', source: '外部信源·重卡换电测算' },
  // source 三档：外部信源 / 经验假设 / 沿用v2.4
};
```

### 4.2 内容 Agent 的输出规范（子 MD 模板）

```markdown
# 第X章：标题

## 核心结论
（一段话，结论先行）

## 一、小节
（论述 + 表格，数据用 {{TOKEN}} 或标注信源链接）
```

### 4.3 校验 Agent 的检查清单

- [ ] 所有数字：要么是 `{{TOKEN}}`（运行时注入），要么标注信源链接；
- [ ] 分母参数（装车规模等）source = 外部信源，非经验假设；
- [ ] 事实性陈述（时间、数字、事件）可追溯到原始信源；
- [ ] 无"方法论痕迹"（不暴露八步法、共振框架等）；
- [ ] 四层 ΔNI 不能简单相加的纪律被遵守。

## 五、与旧版程序的关系（回答"三个程序什么关系"）

| 程序 | 位置 | 角色 | 在新架构中的位置 |
|---|---|---|---|
| `重卡与城配物流换电规模测算_合并对比.py` | 定性分析/ | **分母测算**（车辆数/渗透率S曲线） | 上游：产出 fleetWan 等分母参数 |
| `CATL_换电增量估值模型_v2.0.py` | 定性分析/ | **增量估值逻辑母版**（四层ΔNI） | 中游：engine.js 的 Python 母版 |
| `换电重估_config.js` + `换电重估_engine.js` | 报告/ | **报告专用 JS 引擎** | 下游：HTML 交互用 |

**关键改进**：旧的 `换电重估_量化.js`（已删除）把参数和逻辑混在一起，容易与 Python 母版漂移。现在拆成 config（参数）+ engine（逻辑），且 config 里每个参数标了信源，与 Python 母版的 P 字典一一对应，漂移时可对照核对。

## 六、下一步（Agent 化的落地顺序）

1. **先固化 engine.js（固定逻辑）**：数学公式不变，Agent 不碰；
2. **再让参数 Agent 接管 config.js**：每次数据更新，只改 config，不动 engine；
3. **再让内容 Agent 接管子 MD**：研究推进时，只重写对应章节；
4. **最后让校验 + 装配 Agent 自动化**：数字一致性检查 + token 注入渲染。

**一句话**：这套架构已经把"手动写报告"拆成了"5 个 Agent 各管一段、一个装配 Agent 自动组装"的流水线。唯一还没做的，是把这 5 个 Agent 的 prompt 和工具调用写出来——那是下一步。

# 战略性业务进入分析：推导逻辑定本

> **文档定位**：本文件是修订skill方法论的终极指导。不记录"谁说了什么"、不区分"哪份文档的版本差异"，只记录**经过所有批判和验证后，战略分析的推导逻辑应该是什么，以及为什么必须是这样**。每一个设计决策都有不可删减的理由——如果理由被推翻，对应的设计必须重新审视。
>
> **版本**：V1.0（2026-05-28）

---

## 一、战略分析的根本逻辑：从用户到终局的单向递进+层内迭代

### 1.1 核心原则

战略分析回答一个问题：**某公司要不要进入某新业务？**

这个问题的回答必须遵循一条不可逆的逻辑链：

```
用户愿不愿意买单 → 行业允不允许赚钱 → 公司不做会怎样 → 公司有没有资格做+账算不算得过 → 合作方愿不愿意跟 → 挑战能不能克服 → 综合判断值不值得赌
```

**为什么必须单向递进？** 因为每一层的结论是下一层的前提。如果需求是假的，后面的分析全部失去意义；如果行业不允许赚钱，战略必要性需要重新评估；如果公司没有能力做，账算得再好也是虚的。

**为什么允许层内迭代？** 因为某些层内部存在循环依赖——最典型的是"能力圈"和"算账"：不知道需要多少钱就无法判断能力圈，不知道能力圈有多大就无法确定模型假设。这种循环依赖不能通过强制排序解决，只能通过层内迭代（粗算→能力圈→精算）解决。

### 1.2 层间关系图

```
L-1 问题界定 ──────────────────────────────────────── 分析边界
  │
L0 需求原点 ──────────────────────────────────────── 一切分析的起点
  │  如果需求是假的，以下全部不需要做
  ▼
L1 产业结构 ──────────────────────────────────────── 需求真≠能赚钱
  │  如果行业不允许赚钱，L2的战略必要性需要修正
  ▼
L2 战略必要性 ────────────────────────────────────── 不做的代价+时间紧迫度
  │  如果战略上不必要，以下不需要做
  ▼
L3 能力圈与财务 ──── 粗算→能力圈→精算（层内迭代）─── 有没有资格做+账算不算得过
  │  估值-资源反馈环：精算结果→估值→融资能力→能力圈→精算
  ▼
L4 合作方博弈 ────────────────────────────────────── 我能给合作方什么不可替代的价值
  │  合作方选择受L1竞争格局和L3财务结果约束
  ▼
L5 挑战与克服 ────────────────────────────────────── 我们和合作方一起面对的障碍
  │  挑战识别依赖L4合作方资源
  ▼
L6 终局判断 ──── 底线思维+期望值思维（双轨制）────── 综合判断
```

**回溯规则**：任何一层结论与上层矛盾时，必须回溯修正上层假设。但回溯深度限制为最多两层，且必须给出回溯理由——防止分析瘫痪。

## 二、逐层推导逻辑

### L-1 问题界定

**核心问题**：我要判断什么？边界在哪？

**为什么必须存在**：没有边界的分析会无限扩大。从"宁德要不要做换电"扩展到"补能行业未来十年走向"再扩展到"新能源车产业链重构"——分析范围越大，深度越浅，结论越模糊。

**必须回答的四个问题**：

| 问题 | 为什么必须回答 | 不回答的后果 |
|:---|:---|:---|
| **决策类型**：做不做/怎么做/何时做？ | 不同决策类型需要不同深度的分析 | 分析方向跑偏 |
| **时间范围**：1年/3年/10年？ | 判断的时间有效期不同 | 用短期数据做长期判断，或反之 |
| **资源约束**：可投入的资金和管理带宽？ | 决定分析的颗粒度 | 算出了需要500亿但只能调动100亿 |
| **不可逆程度**：退出代价多大？ | 决定容错空间 | 把可逆决策当成不可逆来做，过度谨慎 |

**输出**：决策边界声明书——一张纸，写明以上四个问题的答案，作为后续所有分析的约束条件。

---

### L0 需求原点

**核心问题**：用户真正在买什么？

**为什么是"用户真正在买什么"而非"用户需不需要这个产品"**：

- 问"用户需不需要换电"→ 陷入"换电vs超充"的技术路线之争
- 问"用户的待办任务是什么"→ 发现用户真正在买的是"确定性"和"风险转移"——这两样东西，超充不一定能提供

**核心工具：待办任务分析（Job to be Done）**

对每一类用户，回答三个问题：
1. **用户雇佣这个产品，要完成的任务是什么？**（不是"补能"，而是"确定性能走"/"不用操心电池衰减"）
2. **现有方案在完成这个任务时的不足是什么？**（超充给了速度但没给确定性）
3. **新方案在完成这个任务上的优势是什么？**（换电给了确定性+风险转移）

**子模块：低端颠覆检验**

区分两类用户：
- **主流用户**：被现有方案良好服务，新方案对他们只是"另一个选择"
- **被过度服务的用户**：现有方案给了他们不需要的东西（15分钟超充），但没给他们需要的东西（3分钟确定性）——后者才是颠覆式创新的温床

**子模块：需求不变性锚点**

在需求分析中，区分三类需求属性：
- **基本不变**：营运车的时间成本永远敏感、用户永远不想操心电池衰减
- **可能变但方向确定**：补能速度会提升但不会超过物理极限
- **高度不确定**：政策变化、用户习惯迁移方向

用不变的锚来验证需求的持久性——如果需求只建立在"可能变"的假设上，这个需求的时间有效期就短。

**为什么需求必须在算账之前**：用户愿不愿意买单 → 决定收入能不能实现 → 决定账能不能算得过。如果需求是假的，算出来的账再漂亮也是空中楼阁。

### L1 产业结构

**核心问题**：行业允不允许赚钱？护城河深不深？

**为什么必须存在**：需求真≠好生意。需求可能很真实，但如果买方议价能力太强、替代品太多、进入壁垒太低，结果就是谁都能做但谁都赚不到钱。

**为什么在"战略必要性"之前**：即使需求是真的，如果产业结构不允许赚钱，那公司做了也赚不到钱——这时候"战略必要性"的判断就需要修正：一个赚不到钱的生意，战略必要性可能不是"必须做"，而是"必须找到不做的替代方案"。

**为什么不在需求之后立即放产业结构**："战略必要性"和"产业结构"是两个不同维度——前者是公司视角（对我有什么威胁），后者是行业视角（这个行业什么结构）。先回答"不做会怎样"（公司紧迫度），再回答"做了能赚钱吗"（行业结构），逻辑上更自然——你先要确认这件事值得分析，再投入精力分析行业结构。但最终版采用了"产业结构在战略必要性之前"的顺序，原因是：如果行业根本不允许赚钱，那"不做会怎样"的紧迫度分析就是浪费时间——一个赚不到钱的生意，即使不做也不会有什么损失。所以产业结构是战略必要性的前提约束。

**核心工具：波特五力 + 护城河评估**

五力模型回答"行业允不允许赚钱"，护城河评估回答"这家公司有没有能力守住利润"。两者缺一不可——五力告诉你行业天花板，护城河告诉你公司能拿到的份额。

**五类护城河**：成本优势、网络效应、转换成本、品牌溢价、规模壁垒。

**子模块：10倍速变化检测**

在产业结构分析中，检测五个维度是否有某个正在发生数量级变化：竞争格局、技术、用户行为、供应链、政策。10倍速变化意味着产业结构可能正在重组——此时五力模型的结论需要标注"高度不确定"。

### L2 战略必要性

**核心问题**：不做会怎样？拖一年又会怎样？

**为什么需要时间紧迫度维度**：不是所有威胁都以相同速度逼近。有些威胁是线性逼近的（每年侵蚀一点份额），有些是加速逼近的（一旦越过某个临界点就不可逆）。"今年不做"和"拖三年不做"的代价要分开计算。

**核心工具：威胁-紧迫度矩阵**

| | 逼近速度慢 | 逼近速度快 |
|:---|:---|:---|
| **影响大** | 有时间准备，但必须行动 | 最高优先级，立即行动 |
| **影响小** | 监控即可 | 关注但不紧急 |

**子模块：不可逆点时间线**

标注每个威胁的不可逆临界点——过了这个点，即使再想做也做不了了。不可逆点越近，战略必要性越强。

**子模块：战略叙事威胁**

除了市场份额层面的威胁，还要评估"战略叙事"层面的威胁——如果竞争对手先做成了，你的"行业领导者"叙事会不会崩塌？叙事崩塌比份额侵蚀更致命，因为它影响估值逻辑、人才吸引力、合作方信心。

### L3 能力圈与财务

**核心问题**：有没有资格做？能力撑不撑得住？账算不算得过？

**为什么能力圈和算账必须合并为一层**：

能力圈不是只有"能调动多少钱"——它是一个多维度的能力体系，每一个维度都和算账形成循环依赖：

| 能力维度 | 对算账的影响 | 算账对该维度的影响 |
|:---|:---|:---|
| **资金能力** | 决定投入规模上限、融资成本 | 算出需要多少钱，才能判断资金缺口 |
| **技术能力** | 决定产品能不能做出来、技术路线成本 | 算出技术投入规模，才能判断技术是否可及 |
| **运营能力** | 决定利用率、服务品质、客户留存 | 算出运营指标要求，才能判断运营缺口 |
| **组织能力** | 决定执行速度、人才密度 | 算出组织规模需求，才能判断人才缺口 |
| **品牌/渠道能力** | 决定获客成本、客户信任度 | 算出获客规模，才能判断渠道是否够用 |
| **生态/关系能力** | 决定合作方撬动难度、资源整合速度 | 算出生态建设投入，才能判断关系缺口 |
| **政策/合规能力** | 决定准入门槛、合规成本 | 算出合规投入，才能判断政策风险 |
| **供应链能力** | 决定成本结构、交付速度 | 算出供应链规模，才能判断供应缺口 |

每一个维度都是：**不知道能力边界就无法设定模型假设，不知道模型要求就无法判断能力缺口**。这种循环依赖不能通过强制排序解决，只能通过层内迭代解决。

**核心工具：粗算→能力圈→精算 三步迭代**

**第一步：粗算（量级估算）**

基于L0-L2的结论，快速估算这个生意对每个能力维度的要求：
- **资金**：大概需要多少钱？（10亿还是100亿？）
- **时间**：多长时间能做起来？（3年还是7年？）
- **收入**：什么量级的收入？（年收入10亿还是100亿？）
- **技术**：需要什么量级的技术突破？（渐进改进还是根本性创新？）
- **运营**：需要多大规模的运营体系？（百站还是万站？）
- **组织**：需要什么量级的团队？（百人还是万人？）
- **生态**：需要撬动什么量级的合作方？（几家还是几十家？）

不需要精确模型，只需要量级——目的是给能力圈检验提供每个维度的锚点。

**第二步：能力圈检验**

在粗算锚点之上，逐维度判断公司有没有资格做：

| 能力维度 | 检验问题 | 圈内/圈边/圈外判断 |
|:---|:---|:---|
| **技术能力** | 核心技术是否在圈内？需要多大规模的技术投入？ | |
| **运营能力** | 业务模式与公司基因是否匹配？运营复杂度能否驾驭？ | |
| **资金能力** | 能不能调动粗算量级的钱？融资渠道和成本如何？ | |
| **组织能力** | 有没有合适的人来做？人才密度够不够？ | |
| **品牌/渠道能力** | 现有品牌能否迁移？获客渠道是否需要重建？ | |
| **生态/关系能力** | 现有合作关系能否复用？需要新建什么关系？ | |
| **政策/合规能力** | 政策环境是否友好？合规门槛多高？ | |
| **供应链能力** | 现有供应链能否支撑？需要新建什么环节？ | |

对每个维度：识别能力缺口，评估缺口补齐的成本、时间和概率。

**关键判断**：如果多个核心维度都在"圈外"，这不是"能力缺口"问题，而是"基因错配"问题——基因错配意味着能力圈无法通过投入补齐，只能通过根本性的组织变革解决。

**第三步：精算（详细财务模型）**

在能力圈约束下建立详细财务模型——每个能力维度的约束都映射到模型假设：
- **运营能力约束** → 利用率上限、服务品质上限 → 收入假设
- **技术能力约束** → 产品迭代速度、技术路线成本 → 成本假设
- **组织能力约束** → 执行速度、扩张节奏 → 时间假设
- **品牌/渠道约束** → 获客成本、客户信任建立速度 → 收入假设
- **资金能力约束** → 投入规模上限、融资成本 → 资金假设
- **供应链约束** → 成本结构、交付速度 → 成本假设
- **政策/合规约束** → 准入成本、合规风险 → 成本假设

**精算内部必须包含两个子步骤**：

**子步骤A：不变性审查**

在建模之前，区分三类变量：
- **锚点变量**（10年不变的东西）：用这些做模型的基础假设。如：营运车的时间成本永远敏感、用户永远不想操心电池衰减
- **敏感性变量**（可能变但方向确定）：做敏感性分析。如：超充速度会提升但不会超过物理极限
- **情景变量**（高度不确定）：做情景分析。如：政策变化、固态电池量产时间

**子步骤B：颠覆性创新检查点**

即使精算模型不支持（IRR不够高、NPV为负），仍需回答：
- 如果竞争对手先做并跨越临界点，既有业务的财务模型会怎样变化？
- 做这个业务的"最坏损失" vs 不做的"最坏损失"——哪个更不可承受？
- 有没有间接价值？（阻止竞争对手垄断、保护既有业务估值逻辑、获取标准定义权）

**估值-资源反馈环**

精算的结果不仅影响公司估值，还通过估值影响能力圈的每一个维度：

```
业务进展好 → 估值上升 → 融资能力增强 → 资金能力扩大
                     → 品牌势能上升 → 人才吸引力增强 → 组织能力扩大
                     → 合作方信心增强 → 生态资源涌入 → 关系能力扩大
                     → 政府关注度上升 → 政策支持增强 → 合规能力扩大
                     → 供应商意愿增强 → 供应链能力扩大
                     → 综合能力圈扩大 → 可以投入更多 → 业务进展可能更好

业务进展差 → 上述全部反向
```

这个反馈环意味着L3不是一次性完成的，而是需要随着业务进展动态更新——能力圈的边界是活的，不是画完就固定的。

### L4 合作方博弈

**核心问题**：我能给合作方什么不可替代的价值？

**为什么不是"谁适合我"而是"我适合谁"**：

从自己的需求出发找合作方 → 找到的是"能帮我的人"，合作松散
从合作方的需求出发 → 找到的是"需要我的人"，合作深度

**为什么在L3之后**：竞争格局决定了合作方的选择空间——如果竞争对手提供了更好的合作条件，你的合作方就会选别人。只有先算清楚了竞争格局和自身能力，才知道能给合作方什么不可替代的价值。

**核心工具：合作方拼图 + 议价能力矩阵**

**合作方拼图**：对每一类潜在合作方，回答：
1. 他们在这个生意里能挣到什么钱？
2. 他们有什么我们需要的资源？
3. 我能给他们什么不可替代的价值？
4. 他们的替代选择是什么？（如果替代选择很强，我们的不可替代性就弱）

**议价能力矩阵**：

| 维度 | 强议价能力 | 弱议价能力 |
|:---|:---|:---|
| **稀缺性** | 合作方资源稀缺 | 合作方资源充裕 |
| **不可替代资源** | 合作方拥有独占资源 | 合作方资源可替代 |
| **切换成本** | 合作方切换成本高 | 合作方容易切换 |

议价能力决定合作模式：面对强议价能力的合作方，必须深度绑定；面对弱议价能力的合作方，松散耦合就够了。

**动态性**：合作是动态的——解决困难越快越坚决，合作面越广。L5的挑战克服进度会反过来影响L4的合作方选择空间。

### L5 挑战与克服

**核心问题**：核心卡点是什么？怎么突破？

**为什么在合作方之后**：挑战不是抽象的——它是"我们和合作方一起面对的"具体障碍。只有先确定了合作方是谁、他们有什么资源，才能准确识别核心挑战。

**核心工具：挑战-可突破性矩阵**

| | 可突破（有明确路径） | 难突破（路径不清晰） |
|:---|:---|:---|
| **影响大** | 优先投入资源突破 | 需要创新性解决方案 |
| **影响小** | 正常推进 | 监控即可 |

**动态反馈机制**：挑战的克服进度影响合作方信心 → 影响合作方投入意愿 → 影响资源可用性 → 影响挑战克服能力。这个反馈环可能是正的（越克服越有资源），也可能是负的（越克服不了越没资源）。

---

### L6 终局判断

**核心问题**：底线在哪？期望多大？

**为什么必须双轨制**：

- 只用底线思维：你知道什么一定不成，但不知道最可能成多大 → 无法决定投入多少资源
- 只用期望值思维：你知道期望回报，但不知道尾部风险 → 可能在最坏情况下翻车
- 两者结合：**底线保生存，期望定节奏**

**第一轨：底线思维**

列出"一定不成的条件"清单——如果X发生，这个业务一定不成。每个条件标注：
- 当前逼近度（低/中/高）
- 逼近速度（慢/快）
- 不可逆临界点

**一票否决权**：如果任何底线条件逼近度达到"高"，无论期望值多高，都必须降档或暂停。这不是否定概率判断，而是划定概率判断的适用范围——在可承受风险范围内，概率判断才有意义。

**第二轨：期望值思维**

在底线之上，做概率加权情景分析：
- 每个情景的概率必须绑定可验证指标
- 指标变化时概率自动调整
- 给出不同情景下的：时间、资金、规模预期

**两轨的结合逻辑**：

```
底线条件全部"低"逼近度 → 正常推进，按期望值分配资源
底线条件有"中"逼近度 → 提高警惕，增加该条件的监控频率，准备应急预案
底线条件有"高"逼近度 → 一票否决或降档，无论期望值多高
底线条件逼近度从"中"升到"高" → 自动触发概率分布调整（悲观情景概率上调）
```

**子模块：战略期权价值**

即使直接经济回报不确定，还需评估间接价值：
- 阻止竞争对手垄断
- 保护既有业务估值逻辑
- 获取标准定义权
- 建立生态锁定效应

这些期权的存在可能使得"做"的决策即使在经济上不划算，在战略上仍然合理。

## 三、元规则

### 规则1：螺旋回溯

任何一层结论与上层矛盾时，必须回溯修正上层假设。

**约束**：
- 回溯深度限制：最多回溯两层
- 必须给出回溯理由——为什么上层假设不成立？
- 回溯后必须重新检验受影响的下游层

**典型场景**：L3精算发现L0的需求假设过于乐观（用户付费意愿比预期低）→ 回溯修正L0 → 重新推演L1-L3

### 规则2：时间有效期

每层判断标注"在多长时间内可靠"。

**为什么必须标注**：今天的正确判断明天可能失效。不标注有效期，读者会默认判断永远有效——这是危险的。

**标注方式**：
- 高可靠性（1-3年基本不变）：如"营运车时间成本敏感"
- 中可靠性（1年内基本不变，1-3年可能变化）：如"超充技术路线"
- 低可靠性（随时可能变化）：如"政策环境"

### 规则3：确定性等级

每层判断标注高/中/低，不确定性高的结论给出关键假设和验证方法。

**为什么必须标注**：不确定性高的结论如果被当成确定性结论使用，会导致决策错误。标注确定性等级的目的是提醒使用者：哪些结论需要持续验证。

### 规则4：第一性原理优先

区分"类比推理"和"第一性原理推理"，优先使用后者。

- 类比推理："别人做过类似的，所以这条路可行"——可能对，也可能陷入路径依赖
- 第一性原理推理："回到最基本的物理/经济规律，从零推导"——更可靠，但更费力

**使用原则**：关键判断（需求原点、终局判断）必须用第一性原理；辅助判断（竞争格局细节）可用类比推理。

### 规则5：动态更新

外部环境变化时从受影响层重新推演；概率绑定可验证指标，指标变化时概率自动调整。

**为什么必须动态**：战略决策不是一次性事件，而是持续过程。环境变化时如果不更新判断，之前的正确决策会变成错误决策。

## 四、框架的适用边界

### 适用

- 大型企业进入新业务领域的战略决策
- 投资机构评估新业务可行性
- 战略咨询项目
- 重资产基础设施投资的进入判断
- 需要多方合作才能建成的生态型业务
- 面临延续性vs颠覆性创新选择的决策

### 不适用

- 创业公司从0到1的决策（没有"能力圈"和"合作方博弈"的筹码，跳过L1/L3/L4）
- 纯技术评估（不涉及商业决策）
- 日常运营决策（不需要如此重的分析框架）

### 与其他框架的关系

本框架是**整合框架**，不是**替代框架**。与其他框架的关系是分层使用：

| 决策复杂度 | 推荐框架 | 本框架的角色 |
|:---|:---|:---|
| 低（日常运营） | SWOT / 精益画布 | 不适用 |
| 中（产品决策） | 波特五力 + JTBD | 简化版（L-1 + L0 + L1 + L6） |
| 高（投资决策） | 本框架完整版 | 完整应用 |
| 极高（产业转型） | 本框架 + 情景规划 + 战争推演 | 作为核心框架，外挂其他工具 |

## 五、框架的局限性

| 局限 | 说明 | 应对方式 |
|:---|:---|:---|
| 底线条件清单可能不完整 | "你不知道你不知道什么"——清单可能遗漏最关键的条件 | 定期请外部视角审查清单完整性 |
| 螺旋回溯可能导致分析瘫痪 | 每层都回溯修正，分析可能永远无法收敛 | 回溯深度限制+设定分析截止时间 |
| 能力圈检验可能过于保守 | 芒格的能力圈检验天然倾向于"不做"——如果严格遵循"只做能力圈内的事"，公司永远不会进入新领域 | 能力圈检验不用于"否决"，而用于"识别缺口"——发现运营能力缺口不是"不能做"的理由，而是"需要多少时间和成本来补齐"的起点 |
| 能力圈判断缺乏量化标准 | "圈内/圈边/圈外"判断依赖经验 | 用"能力缺口补齐成本"和"补齐时间"作为量化代理指标 |
| Job to be Done分析可能过度主观 | 不同分析师对"用户真正在买什么"可能有完全不同的理解 | 用行为数据（转化率、留存率、付费意愿）验证 |
| 粗算→精算迭代可能引入锚定偏差 | 粗算的量级估算可能锚定精算的假设范围 | 精算时独立验证粗算的关键假设；如果精算结果与粗算量级偏差超过一个数量级，重新从粗算开始 |
| 双轨制终局判断可能产生矛盾 | 底线思维说"不能做"，期望值思维说"值得做" | 底线思维有一票否决权；但可通过"战略期权价值"对冲——如果战略期权价值极高，逼近度阈值可从"高"提升到"极高" |

## 七、对Skill设计的指导原则

### 7.1 Skill必须强制执行的内容（不可跳过）

- **信息源标注**：每个关键判断和数据必须标注来源（本地知识库路径或网络URL），无来源的判断不得写入正文。每层小结必须包含"关键信息源"汇总。合法信息源仅两类：①项目目录中已人工筛选沉淀的可靠信息（追溯至`d:\AI\证券投资\投研`一级子目录）；②网络搜索获取的公开信息（需标注URL和日期）
- **L-1问题界定**：不能跳过边界设定直接进入分析
- **L0 Job to be Done**：不能用"需求验证"替代"待办任务分析"
- **L1五力+护城河**：不能跳过产业结构直接谈战略必要性
- **L3粗算→能力圈→精算迭代**：不能跳过能力圈检验直接建精算模型
- **L6双轨制**：不能只用概率或只用反概率
- **5条元规则**：每层分析结束时必须执行（螺旋回溯检查、时间有效期标注、确定性等级标注）

### 7.2 Skill应该建议但允许灵活调整的内容

- 每层分析的详细程度（取决于决策的不可逆程度）
- 合作方分析的范围（如果业务不需要合作方，L4可以简化）
- 挑战分析的深度（取决于L3暴露的能力缺口大小）

### 7.3 Skill应该留给分析师判断的内容

- 具体的数据来源和假设取值
- 各层分析的结论（框架只规定"问什么问题"，不规定"答案是什么"）
- 最终决策——框架提供多维度分析，但"做还是不做"的判断权始终在决策者手中

### 7.4 Skill设计的核心原则

> **"不是给答案，而是确保你问了所有该问的问题。"**

这个原则贯穿整个框架设计——每一层不是一个"结论生成器"，而是一个"问题清单"。框架的价值不在于替你思考，而在于确保你没有遗漏任何一个该思考的维度。

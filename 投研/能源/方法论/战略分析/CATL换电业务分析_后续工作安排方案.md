## 三、Q1/Q2/Q3处理方式：写新文档，不直接改原文件

### 3.1 为什么不直接改原文件

| 理由 | 说明 |
|:---|:---|
| ① 历史记录完整性 | 原Q1/Q2/Q3是真实讨论过程的记录，包含批判-修正的完整链条，直接改会丢失过程信息 |
| ② 内容越界混合 | 原记录混合了多步内容（Q2越界到Step3，Q3越界到Step6-7），无法通过简单修改分离 |
| ③ 符合框架设计 | 框架文件步骤4明确："存量资料人工校准+AI二次提纯"——原记录是存量资料，新文档是提纯产出 |
| ④ 职责单一原则 | 新工作流要求每步职责单一，原记录不满足，必须按新结构重组 |

### 3.2 原文件处置

- 原Q1/Q2/Q3记录 **保留不动**，移到`工作记录/归档_`前缀
- 作为"存量资料"，供新文档编写时提取有效内容
- 新文档在需要引用时标注"引自归档Q2第X部分"

## 五、关键判断：是否现在就执行全部？

**建议分批执行，优先级如下**：

1. **立即执行**：Phase 1.1（升级格式规范）+ Phase 2（文件迁移）—— 这些是基础设施
2. **次优先**：Phase 1.2-1.4（补全Step1/Step2工作流 + 三轨模板）—— 建立完整方法论标准
3. **然后执行**：Phase 3.1-3.3（编写前3步新记录）—— 按新标准重做CATL换电分析
4. **穿插执行**：Phase 4（红队批判）—— 与Phase 3同步

**不建议一次性全部完成**，原因：
- Phase 3每步都需要人工验收裁定，不能AI自主完成
- 红队批判需要异构模型独立窗口，无法在单次对话中完成
- 应该按框架文件步骤5的要求："选择问题链的一个环节→给AI下指令→验收→判断→写入报告→下一个"

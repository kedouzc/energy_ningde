## 用户需求

按 `宁德时代/业务/换电/工作记录/研究历史记录.md`（2026-08-07 复盘）的方法论结论，为 `D:\AI\证券投资\投研\能源` 绘制一张「研究探索地图」，标清各主题的相关性、探索路径与进展，并让地图真正落地复盘中「坑二（贪跨领域泛化）」「坑三（贪业务协同故事）」的应对方式——即「留口子 + 研究地图 + 先 close 当下」。

用户已确认三项形态选择：

1. 范围：分层版（宁德当下课题为主图 + 留口子区 + 能源级仅轻索引，不贪大）
2. 位置：两处（能源顶层总图 + 宁德时代内部细图）
3. 深度：完整版（关联图 + 状态清单表 + 留口子区 + 未决张力标注 + 更新纪律）

## 产品概述

把「研究地图」重新定义为**探索状态地图（作战图）**：它回答的不是"文件在哪"（这已由 `_方法论索引/00`、`02`、`换电/readme.md` 覆盖），而是"**我研究到哪了、哪些口子还开着、下一个该收哪个、哪些结论互相打架**"。

产出两份 Markdown：

- **顶层总图** `能源/研究探索地图.md`：能源全域的一屏鸟瞰 + 留口子区（跨领域分支的存放处）+ 能源级轻索引（框架/远景/光伏/演化过程各一行入口）+ 更新纪律。
- **宁德细图** `宁德时代/_方法论索引/03_探索状态地图.md`：宁德当下核心课题的详细作战图，含各主题节点状态、跨主题连线、未决张力、待查锚点清单。

并把两份地图挂接进 `README.md` 与 `当前思考.md`，避免成为孤岛文件。

## 核心功能

**1. 主题关联图（Mermaid）**
画出 换电 / CTC / 滑板底盘（磐石·CIIC）/ 动力电池制造 / 储能 / AIDC / 估值范式 / 竞争格局 之间的真实连线，连线类型区分：物理互斥、同源标准化、协同（待决）、证伪关闭、估值触发。

**2. 节点状态清单表**
每个主题标注五档状态：已 close 有结论 / 进行中 / 待查·口子开着 / 已证伪关闭 / 未决张力；并附核心结论一句话、代表文件路径、下一步动作。

**3. 留口子区（回应坑二的实体载体）**
集中收纳被主动关闭的发散分支：贝壳 ACN 类比、电池↔半导体↔AI 同构联想、电池数据信息变现、换电站储能套利。每条写清：关闭原因 / 回接触发条件 / 回接锚点文件，确保未来研究芯片或 AI 时能顺线索回接，让这次发散不白费。

**4. 未决张力标注（回应坑三）**
显式标出文档间互相打架处：`2030年业务线战略研判.md` 主张"换电+储能+AIDC 协同、应加大投入"，而复盘坑三判定同一串联为"虚假协同"。标为待决、不抹平，并写明裁决前提"先把换电本身 close 掉"。

**5. 待查锚点汇总**
汇总复盘 §六 三条待查（CTC 合作研发能否锁单保毛利 / 磐石 vs 悠跑·Rivian 竞争卡位 / 三条路是否穷尽车企生存状态）、CTC 研究 §7.1 待查项、`00_文件组织总览.md` 的 V2.0 待办，形成统一的"开放边"清单。

**6. 有效性评价与更新纪律**
在地图开头写明本图的定位与边界（为何不做大而全的全景挂图），并给出 30 秒更新纪律（每次复盘或 close 一个课题即更新对应节点状态与日期），防止重蹈 `当前思考.md` 停更在 2026-04-13 的覆辙。

## 视觉效果

纯 Markdown 呈现，沿用仓库既有风格：Mermaid 代码块作关联图、表格作状态清单、ASCII/引用块作层级说明；状态用统一图标标记（已 close / 进行中 / 待查 / 已证伪 / 未决张力），文内所有文件引用均为可点击相对路径链接。

## 技术选型

- **载体**：Markdown（GFM），与仓库现有全部研究文件一致
- **图形**：Mermaid `flowchart` / `mindmap`，沿用仓库既有习惯（`宁德时代/报告/宁德时代研究_mermaid.md` 已使用 Mermaid 横向图）
- **链接**：相对路径 Markdown 链接（Obsidian / VSCode 均可跳转），不引入任何构建工具或脚本
- **无新增依赖**：不写 JS/Python，不改动 `common/md-loader.js` 与 `财务模型/engine/`

## 实现策略

### 核心思路

把地图定义为 **"状态层" 而非 "索引层"**。仓库已有四份索引解决"东西在哪"：

- `宁德时代/_方法论索引/00_文件组织总览.md`（目录规则 + 三条红线 + 工作流）
- `宁德时代/_方法论索引/02_主报告源材料映射表.md`（主报告章节 ← 源文件血缘）
- `宁德时代/业务/换电/readme.md`（换电四层金字塔架构）
- `宁德时代/业务/换电/历史文件覆盖映射.md`（旧文件 → 新报告覆盖校验）

新地图**不重复文件清单**，只承载三类既有索引都没有的信息：**状态（研究到哪）、口子（关了什么、怎么回接）、张力（哪里自相矛盾）**。这是复盘 §七.2 对研究地图的原始定义——"存放暂时关闭但留了口子的发散分支"。

### 关键决策

**决策 1：两层分工，杜绝内容重复**

- 顶层 `研究探索地图.md`：全域鸟瞰（宁德为主节点，远景/光伏/框架各一行）+ **留口子区放这里**（因为贝壳/芯片/AI 属于跨出能源域的分支，放能源顶层才符合"下次开疆拓土时能找到"的语义）+ 更新纪律
- 宁德 `03_探索状态地图.md`：宁德内部主题的详细状态表、跨主题连线图、未决张力、待查锚点清单
- 两份文件互相双向链接；顶层不复制细图表格，只给状态摘要行 + 跳转链接

**决策 2：状态图标统一为五档**（复用 `历史文件覆盖映射.md` 已有的四级标注习惯并扩展）
`✅ 已close有结论` / `🔄 进行中` / `🔍 待查·口子开着` / `❌ 已证伪关闭` / `⚠️ 未决张力`

**决策 3：地图本身不产生新结论、不作为信源**
严格遵守既有纪律（换电目录下文件互不引用为信源，避免循环论证）。地图只做**状态标注与指针**，所有结论必须回链到原文件；地图文件顶部显式声明"本文件为状态索引，不可作为任何测算的信源"。

**决策 4：Mermaid 节点文本避坑**
Mermaid 中文节点文本内若含 `（）`、`/`、`:` 等字符需用引号包裹节点标签（如 `A["换电 ✅"]`），避免渲染报错；连线标签统一用 `-->|物理互斥|` 形式。控制单图节点数在 15 个以内，超出则拆图，保证可读性。

**决策 5：轻量优先，防过期**
两份文件均控制篇幅（顶层约 150 行、细图约 250 行以内），只写状态不写论证。文件头部写 `最后更新` 日期 + 更新触发条件，README 挂链接时同步标注更新纪律。

## 关键结构定义

节点状态表的统一列结构（两份文件共用，保证可机读、可增量更新）：

| 列 | 含义 |
| --- | --- |
| 主题 | 研究对象节点名 |
| 状态 | ✅已close / 🔄进行中 / 🔍待查 / ❌已证伪 / ⚠️未决张力 |
| 核心结论 | 一句话，须可回链到原文件 |
| 代表文件 | 相对路径 Markdown 链接 |
| 下一步 | 具体动作或"暂关闭·见留口子区" |
| 更新日期 | YYYY-MM-DD |


留口子区的统一条目结构：

| 列 | 含义 |
| --- | --- |
| 分支 | 被关闭的发散方向名 |
| 当时为何被吸引 | 一句话还原动机（对应坑二/坑三） |
| 关闭原因 | 证伪结论或"优先级让位" |
| 回接触发条件 | 满足什么条件时值得重新打开 |
| 回接锚点 | 届时该从哪个文件哪一节读起 |


## Agent Extensions

### SubAgent

- **code-explorer**
- Purpose: 扫描尚未细读的能源级目录（`框架/`、`远景科技/`、`演化过程/`、`Clippings/`、`光伏/`、`草稿/`、`问题清单/`、`多AI辩论/`），提取每个域的主题、最新进展与代表文件，供顶层总图的"能源级轻索引"与鸟瞰图使用；同时核对宁德细图将引用的全部文件路径真实存在。
- Expected outcome: 得到一份逐域的"主题 + 状态 + 代表文件路径"清单，且所有待写入地图的链接路径均已核实无误，确保地图零编造。

# 研究项目约定

> **这一页是全部约定。** 每条规则都写了"谁、什么时候、怎么查"。细节住 `约定/` 目录：动作清单在做那件事时读，细则在需要时查。
> 旧版全文（2026-09-26 重构前，752 行）存 `_archive/研究项目约定_重构前_20260926.md`；旧编号对照见文末。
> 为什么这样改：规则越写越长，AI 读了也会漏；真正每次都被执行的，只有变成构建闸门的那几条。所以本页只留规则本身，每条绑一个检查点。

---

## 一、目标与分工

**研究目标链**（每轮都对照它，看有没有偏离）：

```
投资结论 ← 兑现年价值 ＝ 份额 × 单位经济 × 倍数
          份额 ＝ 可及比例 × 系统成本低于替代的车占比
          单位经济 ＝ 终局三价（充电服务费、换电服务费、电池租金）× 成本 → 站与电池银行两本账
          倍数 ＝ 兑现年之后的成长与风险（估值专题）
```

**分工**：研究者出判断与取舍；AI 出材料、结构、计算和起草。研究者不读程序，读正文、口径文档和沙盘。

## 二、协作规则（C）

| # | 规则 | 检查点 |
|---|---|---|
| C1 | **每轮一个主问题**；开头说明它在目标链的哪个节点。顺带发现进交接 §5.0 待办池，不当轮追 | 回复开头 |
| C2 | **先对齐定义，再算。** 一个词（利用率、份额、覆盖）在研究者和 AI 心里可能不是一回事；对结果影响大的量，先用一句话写出它的定义和算式，研究者认可了再往下算 | 引入或改动任何关键量之前 |
| C3 | **分级**：每个发现先测对结论的影响。宁德归属现金流折现或份额变动 ≤ 5% 的，AI 自己定、记 DECISIONS、回复里一句话告知；> 5% 或涉及框架的，才提给研究者 | 每个发现 |
| C4 | **提问与建议讲透**：影响哪个结论、多大 → AI 的倾向与依据 → 需要研究者给什么（二选一／数据／确认）。不列不带目的的"请核查"清单 | 每个提问 |
| C5 | **发现讲到底**：说一个问题，必须同时说它影响哪些参数、哪些读数、结果变不变、变多少；不影响也要明说"不影响，因为……" | 每个发现 |
| C6 | **每轮回复末尾有一张"落点表"**：这轮的每个分析与修改，写进了哪个文件的哪一节；分析类回答也要说"已写入 X／未写入，原因"。研究者按这张表核查，不用自己找 | 每轮回复 |
| C7 | **每轮回复结尾写进展小结与下一步** | 每轮回复 |
| C8 | **讨论当轮落盘**：判断变了 → DECISIONS；当前态变了 → 交接；口径变了 → 口径文档；论证变了 → 章或专题 | 每轮收尾走 `约定/清单_每轮交付.md` |
| C9 | **研究者手上的文件是正本**：改任何文件前重新读当前版本，不用缓存 | 每次写文件前 |
| C10 | **不可逆的操作先问**（删除、覆盖研究者改过的文件） | 执行前 |

## 三、研究方法（M）

| # | 规则 | 检查点 |
|---|---|---|
| M1 | **以终为始**：动笔前写下三行——要判的命题（可判真假）、判它要哪几个数、看到什么会改判。每段最后一句要回答命题，中间量后面紧跟"所以它怎么影响结论" | 写任何论证前 |
| M2 | **终局＝均衡**：终局价格由对手成本曲线与自由进入推出，不许拍；对手取兑现年的对手，先找最强的那一个 | 定价格类参数前 |
| M3 | **结构不能让结论由拍值决定**：一个"占比""过滤器"在基准处恒为 1 或恒为 0，等于没有；最大的驱动数必须有推导或有信源 | 改模型结构时 |
| M4 | **成对的数必须同源**：比例、差额、"少活几成"，分子分母出自同一家、同一场发布或同一研究；比例可搬，水平不可搬。比较两种设计的持有成本，寿命与单价都要成对 | 定成对参数前；程序查 `pair_sources` |
| M5 | **每个比例写清基数**：占哪一年的哪个价、哪个口径（电芯／系统、上险／批发）；乘之前先换到同一基数 | 引入比例时 |
| M6 | **三档并报**：悲观／中性／乐观一起给；越过门槛的那一档，从中性逐个拨参数，列出起作用的是哪几个、会不会真的发生 | 给结论时 |
| M7 | **部分说明整体先说代表性**：例子占全体多少，全体的加权结果是多少 | 举例时 |
| M8 | **异常先解释再取舍**：一个数太便宜或太贵，要么口径读错、要么先验错 | 遇到对不上的数 |
| M9 | **理论在前，跟踪在后**：论证用本质推理加已公开信息；要等披露的数只进跟踪清单 | 写论证时 |
| M10 | **本质与载体分开**：电池归谁持有、谁管理是本质；换电、整车租赁加充电是载体 | 写论证时 |
| M11 | **每次修订论点写一句"什么情况下我放弃这一版"**（现在不触发、将来可能触发） | 改论点时 |
| M12 | **动手前先读已有成果**：找信源先查台账；讨论本质问题先读第 2 章与"业务本质"专题；改参数先读它在 base.toml 的注释链；新写东西先在整个研究目录里搜 | 动手前 |

## 四、数据与计算（D）

| # | 规则 | 检查点 |
|---|---|---|
| D1 | **参数带信源**；没有的显式标"经验假设"或"声明值"，不装精确（取整档） | 改参数时；`tree.py` 查叶参数信源 |
| D2 | **引用的信源必须在台账里**（`audit/信源审计台账.md`）；新信源当轮登记 | 构建闸门 `state_lint.check_sources` |
| D3 | **输入只有一个家 `configs/base.toml`，输出只有一个家 `configs/metrics.toml`**；公司宣发的规划数只做交叉验证，不做输入 | 改参数时 |
| D4 | **同一功能一个实现**；叙述、专题、口径共用一个注入器 | 写程序时 |
| D5 | **文档里模型算出来的数一律写占位符**，由程序注入；叙述层不许裸数字；口径里输入写键名与理由，口径自身的取值（取下沿、分几段）才手写 | 构建闸门 `inject` |
| D6 | **数取不到要闹出动静**：nan 不许安静地流进文档 | 构建日志；落点表前查一遍 nan |
| D7 | **断言写成恒等式**（如"站 ＋ 电池银行 ＝ 系统"逐池配平）；容差只吸收浮点误差 | 写断言时 |
| D8 | **改一个数，同时写"为什么是这个数、换成别的会怎样"**，写在参数注释与对应口径文档里 | 改参数时 |
| D9 | **跑之前写预期**（`configs/changelog.toml` 的 expect），跑完对照；新加的闸门做一次负向测试 | 每轮改模型 |
| D10 | **改完跑 build、tree、run 三条命令**，全绿才算改完 | 每轮收尾 |
| D13 | **程序算的每一张表，口径里必须同时写「算式」「输入」「算例」**：算式用大白话写出每一项怎么算；输入表写键名、取值、信源、为什么取这个；算例挑一行按计算器一步步走（中间数由程序注入）。研究者不读程序，看不到这三样就无法复核 | 构建闸门 `state_lint.check_calc_explained`（旧节列待补账） |
| D11 | **文件不许悄悄消失**：上次构建时在的源文件这次不在，构建失败；有意删除要登记到 `build/_inventory_removed.txt` 并写理由 | 构建闸门 `state_lint.check_inventory` |
| D12 | **改一个文件，只用"读原文件 → 改 → 写回同一路径"**；不用会整体替换目录或文件的操作；写完核对文件还在、行数合理 | 每次写文件 |

## 五、文件（F）

| # | 规则 | 检查点 |
|---|---|---|
| F1 | **三分法**：状态（现在是什么，覆盖写）、过程（DECISIONS，只追加）、产物（程序生成） | 新建文件前 |
| F2 | **状态文件只写现在**：口径、章、专题、交接不写"上一版如何""更正"；来历一行指向 DECISIONS | 构建闸门 `state_lint` |
| F3 | **生成稿与源同住**：`X.src.md` 旁边是 `X.md`（勿手改）；`outputs/` 只放最终产品，`build/` 放中间数据 | 目录约定 `src/paths.py` |
| F4 | **新建文件三问**：它是哪一类？已有文件能不能涵盖？进哪个目录？ | 新建文件前 |
| F5 | **DECISIONS 条目格式**：触发／查下来／改成什么／影响／我错在哪·学到什么（写成"下次遇到 X，先问 Y"）；→skill 标记；索引表完整 | 每条改动 |
| F6 | **归档先做覆盖检查**，结果记进 DECISIONS | 归档前 |
| F7 | **给人读的文件写成常识能懂的话**：结论先行、每个数说来历与意思、详细算式进附录 | 交稿前走 `约定/清单_写文档.md` |

## 六、`约定/` 目录

| 文件 | 什么时候读 |
|---|---|
| `约定/清单_每轮交付.md` | 每轮回复之前 |
| `约定/清单_改参数与模型.md` | 改 base.toml 或 src 之前 |
| `约定/清单_写文档.md` | 写或改章、专题、口径之前 |
| `约定/细则_文件与DECISIONS.md` | 新建目录、归档、写 DECISIONS 格式有疑问时 |
| `约定/细则_交互件.md` | 改沙盘或任何 HTML 之前 |
| `约定/细则_协作与复核.md` | 需要查旧协作协议、复核协议、异构审阅的细节时 |
| `约定/细则_计算与信源原文.md` | 需要查 D、M 组规则的原始论证与事例时 |

细则是原文照搬、留作查证；它们与本页冲突时以本页为准。

# narrative/ —— 叙述层源文件

这个目录放**人（或 LLM）写的正文**。`outputs/` 下的同名 `.md` 是生成物，改了会被覆盖。

## 两层结构（2026-09-06 起）

```
narrative/
  chapters/   八章正文，数量固定 —— 骨架见 框架提案.md §1.1
  topics/     可被多章引用的论证专题 —— 提升判据见 框架提案.md §1.4
```

**2026-09-07 改：先写 `chapters/`，专题按章的需要重写。**
理由见 `交接.md` §5.0——没有章，专题的对错无法验证。`topics/` 现在一律是素材。
**一条结论只能有一个 home**——写在专题里，章里引用它，不要两边各写一遍。

专题的提升判据（满足任一才提，默认不拆）：
① 两章以上引用；② 更新周期与模型无关；③ 是一条已定决策的完整论证。

> `inject.py` 递归扫 `narrative/**/*.src.md`，两个子目录都受下面这条纪律约束。
> **文件名必须以 `.src.md` 结尾**，否则会被静默跳过、不受检查。

> **例外：`一页纸.md` 故意不带 `.src.md` 后缀**——它是沙盘 HTML「结论校验 · 一页纸」区块的唯一内容源，由 `src/onepager.py` 显式调用**同一套** `inject.lint()` / `inject.lint_names()` / `inject.inject()`（裸数字同样会被中断、占位符同样写 `{{中文名}}`），纪律不打折，只是不产出静态 md、也不进 `build.py` 的注入流程。

> **`沙盘结论区.md`（①顶部结论 + ②定性逻辑）同样受本目录纪律管**：它也不带 `.src.md`
> 后缀（由 `src/verdict.py` 读取、渲染进沙盘 HTML），占位符写法与这里**完全相同**
> `{{中文名}}`，中文名＝`configs/metrics.toml` 的 `label`（`{{终局年}}`、`{{年换电交易电量}}`），
> 由 `lab.resolve()` 寻址；写内部名同样在生成期中断。改文案只改这个 MD 再重生成即可。

## 一条纪律

**这里的 `.src.md` 不允许出现任何字面数字。**

数字只能写成占位符，由 `python src/build.py` 从 `outputs/facts.json` 注入：

| 写法 | 注入结果 | 用在哪 |
|---|---|---|
| `{{可归因换电增量价值}}` | `5,698.3 亿元`（数值＋单位） | **默认**。单位由 `configs/metrics.toml` 的 `unit` 决定，MD 里**不要再手写单位** |
| `{{可归因换电增量价值:n}}` | `5,698.3`（裸数字） | 表格列已标单位、或单位必须紧跟数字时（如「约 {{终局年:n}} 年建成」）。用了 `:n` 要核对单位与字典一致 |

写错（字典里没有）**不静默变 `[待补]`**：构建会报「找不到」，并列出最像的 3 个候选，照着改 MD 即可。
写内部名（程序里的 key）会被 `lint_names()` 拦下——名字一律写中文，见下面「有哪些事实可以用」。

白名单（可以直接写）：年份、`§4.2.1` 这样的章节号、`v4.3` 这样的版本号、
有序列表序号、`Q1`～`Q4`、行内代码与代码块、Markdown 链接目标。

## 为什么这条纪律要这么硬

以前叙述层允许手写数字，于是同一个「可归因换电增量价值」在三份文档里出现了三个值：

| 文档 | 值 |
|---|---|
| 决策快照 / 骨架报告 | 5,698.3 亿 |
| MANIFEST 快速导读 | 6,724.5 亿 |
| 叙述报告 | 8,026.4 亿（而且拆法都不一样） |

`backscan.py` 是事后字符串抽检，只在想起来时跑，必然漏。
改成占位符之后，检查从"比对数字"变成"文件里还有没有裸数字"——
一个正则就能穷尽，**不可能漏**。

## 有哪些事实可以用

`outputs/facts.json` 是完整清单（事实包），每条带 `label`（中文名）、`from`
（出处程序 `src/<source>.py` ＋ 快照取值路径）、`unit`、`note`（口径说明）。

**写 MD 只写中文名**，没有第二种写法：`{{可归因换电增量价值}}` / `{{年换电交易电量}}`。
中文名按 2026-09-13 定稿的两层住在两个文件，写法完全一样：
* **模型输出**（程序算出来的量）→ `configs/metrics.toml` 的 `label`（`{{年换电交易电量}}`、`{{可归因换电增量价值}}`）；
* **输入**（被叙述引用的参数：终局年、WACC、各条体检线、市占率分母）→ 在 `configs/base.toml` 功能段**就地信封化**的 `label`（参数原位置写 `<键>.v` ＋ label/unit/…，如 `{{终局年}}`、`{{WACC}}`）；研报倍数/TCO 等外部引述 quote 住在 base.toml 末尾 `[[external_quote]]` 的 `label`（`{{重资产基建运营族·区间下沿}}`）；
* **信源链接** → 见下文 `src.*` 例外。

`src/facts.py` 只做装配（模型输出＋就地信封参数/外部引述＋信源台账三类合并成
facts.json），不定义任何参数、中文名或口径——改名改单位都在对应 toml 里做。

程序内部名（`finance.wacc` / `swap.ebitda` / `ops.annual_energy`…）**只在 `.py` 与 `.toml`
里出现，不进 MD**：本目录下所有 md（含 `一页纸.md`、`沙盘结论区.md`）于 2026-09-12
已全部改成中文名；`inject.lint_names()` 是防复发的闸门——谁再写内部名，构建中断并点名
（`python src/inject.py --lint-only` 可单独跑）。它不是"推荐写法"，是**唯一写法**。

**唯一例外：`src.*` 信源**（`{{src.nea_elec_2025}}`）——它引的是
`audit/信源审计台账.md`「信源索引（机读）」表里那一行（名称/URL/抓取日期/分级四件套），
名字就是台账的机读主键；它的中文名是整句信源名，写进占位符反而不可读。
写错（字典里没有）**不静默**：构建会报「找不到」并给最像的 3 个候选。
查全部数／某个数的出处程序：`python src/lab.py metrics` ／ `python src/lab.py metrics 年换电量`。

**新增一个"模型算出来的数"：** 在 `configs/metrics.toml` 登记一行
（`at` 写快照取数路径 ＋ `source` 写程序名）。`facts.py` 会自动把它合并进事实包，
**不要在字典里写公式**，计算逻辑留在对应程序（scale/capex/business/…）；
派生量先在计算程序算好挂到快照字段，再登记（派生该放哪见 `src/README.md`）。

**还有一类事实不是模型算出来的：外部引述（quote）**（`ext.*`，可比公司倍数、第三方
TCO 测算等），住在 `configs/base.toml` 末尾的 `[[external_quote]]`——
* 自带 `text`（可写区间）/`value`，每条必须带 `src`（台账机读表 key）
  与 `as_of`（引用时点）——理由见 `DECISIONS.md`「2026-09-05i」：
  **引用一个时点数，必须写清它是哪个时点的。** 引述信源 URL 的唯一家是信源台账，条目里不贴链接。

**被叙述引用的输入参数**（终局年、driver、外锚、阈值）不另开登记表：在 base.toml
功能段原位置**就地信封化**（`<键>.v` ＋ `label`/`unit`/`decimals` 等呈现要素），
注册表 key 就是点分路径（如 `meta.target_year`），由 `lab.load_envelopes()`
自动发现并升格进结果注册表。单位独立成字段，因此支持「带单位」与「裸数」两种引用。

## 待复核是什么意思

每个段落记住它引用了哪些事实、当时是什么值（存在 `outputs/narrative_state.json`）。
重跑后某个事实的变动超过它的 `watch` 阈值，引用它的段落会被标成「待复核」：

```
第108行 **第一，估值口径是最大的一处判断……
    EBIT: 0.2522 → -57.76（-22999.8%，阈值 ±100%）
```

**数字已经自动更新了，标出来是因为判断可能需要跟着改。**
上面这个例子里 EBIT 由正转负——数字是对的，但那一段"账面接近盈亏平衡"的说法
就不再成立了，需要人重写一句。改一个参数不必重读全文，只看被标出来的段落。

## 日常怎么用

```bash
python src/build.py          # 跑模型 → 出事实包 → 检查 → 注入落盘
python src/inject.py --lint-only   # 只想检查有没有裸数字，不写文件
```

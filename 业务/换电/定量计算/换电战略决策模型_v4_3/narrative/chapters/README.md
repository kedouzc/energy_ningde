## 主张 vs 引用（2026-09-11 定）

> **一个数可以被多个章引用，但只能有一个章「主张」它。**
>
> - **主张（`owns`）** = 这一章对它负责：论证它、给出它的推翻条件、它越阈值时标这一章待复核；
> - **引用（`uses`）** = 借它做下一步推论，不对它负责。

这条解决的是"两章都收同一个数算不算重复"——**不算重复，但只能有一个主张方**。
例：制造侧增量由第 2 章**主张**（不做会失去多少），第 6 章**引用**它作为"冲击"的一半，
而第 6 章主张的是增量价值合计与拍定倍数。`inject.lint()` 会检查同一个 key 不能有两个主张方。

## 定量收口与定性收口

| 字段 | 定义 | 数量 | 作用 |
|---|---|---|---|
| **主张**（`owns`） | 定量收口：这章要**证明**的数，它翻了这章结论就翻 | **1–2 个**，必须少 | 判成立与否 |
| **定性收口**（`qual`） | 纯定性章的收口：**外部可观察的事实**（模型算不出来） | 一句话 | 让定性章也可证伪 |
| **支撑**（`support`） | 论证过程中**引用**的数 | **5–10 个**，该丰富 | 让读者能跟着算 |

两者至少要有一样——都没有，这章就是散文。

> 举例：第 3 章"目标市场"主张的是"营运车合计"与"重卡 TCO"，而"保有量 → 更新周期 →
> 电动化 → 换电渗透 → 本方市占"那五级漏斗**全是支撑读数**。主张如果也写五六个，就等于没收口。
>
> 纯定性章举例：第 1 章"非共识在哪"的收口是**共识锚三条外部观察**（卖方用不用 SOTP／
> 换电有没有被单独列示／有没有机构给过独立估值）——这是外部形式证据，不该进 `METRICS`。

## 文件头格式（机械可判）

每份 `.src.md` 开头必须有这几行，顺序固定：

```markdown
# N 标题

- 主张: <metric_key>[, <metric_key>]     ← 必须存在于 lab.METRICS；纯定性章可空
- 定性收口: <一句话外部可观察的事实>      ← 纯定性章必填，定量章可省
- 引用: <metric_key>, ...                 ← 借用但不负责的读数
- 支撑: <metric_key>, ...
- 点名专题: <专题名>, ...
```

- 多个 key 用**逗号**分隔写在同一行（不写多行，便于 lint 一次解析）；
- 声明里的**说明文字不会被当成 key**（lint 只认 `a.b` 这种形状），所以可以放心写
  `- 主张: （纯定性章，无模型数收口）`；
- `inject.lint()` 检查：有没有收口（定量或定性）、key 在不在注册表、**有没有被别章主张过**。

## 纪律

- **不许出现字面数字**——数字一律 `{{占位符}}`，从 `facts.json` 注入（年份等白名单除外）；
- **不许出现裸链接**——信源只写 `{{src.xxx}}`，URL 的唯一家是 `audit/信源审计台账.md`；
- **专题是素材，不是成品**——一份专题定稿，当且仅当它被某一章点名、且写那一章的过程中
  没有回来改它。在此之前 `../topics/` 一律原地不动；
- **本节是占位骨架**——目前九份只有标题与收口，正文待写。立骨架是为了让 lint 有对象、
  让跳转有落点，不是交付。

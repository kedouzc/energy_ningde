| Agent | 职责 | 触发时机 |
|:---|:---|:---|
| **Quality Gate Agent** | CQ四重检查（知-Q/行-Q/合-Q/一-Q）+逻辑一致性+数据溯源 | 每步完成后 |

**判断力增强流水线**：

```
Analysis Agent 产出结论
       │
       ▼
┌──────────────────┐
│ Fact-Check       │  对每个关键结论：
│ Gateway          │  ① 联网搜索相关事实
│                  │  ② 多信源交叉验证
│                  │  ③ 标注信源（URL+日期+摘要）
│                  │  ④ 标记"有信源支撑"/"无信源"/"信源矛盾"
└──────┬───────────┘
       │ 只有"有信源支撑"的结论才进入Expert Lens
       ▼
┌──────────────────┐
│ Expert Lens      │  在信源基础上做判断：
│ Agent            │  ① 每个专家视角引用具体信源
│                  │  ② 判断基于事实，而非推测
│                  │  ③ 无信源的结论标记为"需人工验证"
│                  │  ④ 综合意见+分歧点+人工审核建议
└──────────────────┘
```

> **核心设计逻辑**：Expert Lens的幻觉风险来自"无信源的推测"。通过Fact-Check Gateway前置，确保每个结论背后有搜索到的信源，Expert Lens是在信源基础上做判断，就不会出现幻觉。无信源的结论不进入Expert Lens，而是标记为"需人工验证"。

## 三、核心创新：事实核查网关 + 专家视角模拟机制

### 3.0 事实核查网关（Fact-Check Gateway）

#### 3.0.1 为什么需要事实核查网关？

Expert Lens Agent的核心价值是"用专家视角做判断"，但判断的质量取决于输入的质量。如果输入的结论没有事实支撑，专家视角就会在空中楼阁上做推理——这就是幻觉的根源。

**问题**：Agent产出的结论分三类：
1. **有信源支撑的事实判断**——如"中石化2025年与宁德签1万座合作，2026年6月又与比亚迪签2万座合作"（可搜索验证）
2. **逻辑推演但无直接信源**——如"华为'不排斥'策略会削弱宁德议价力"（逻辑成立但需信源佐证）
3. **纯推测**——如"某车企内部正在讨论加入换电联盟"（无任何信源）

如果Expert Lens在第2、3类结论上做判断，就会产生"专家视角背书的幻觉"——看起来有6个专家同意，但基础前提本身就是推测。

**解决方案**：在Expert Lens之前插入Fact-Check Gateway，对每个关键结论执行搜索→交叉验证→标注信源。只有"有信源支撑"的结论才进入Expert Lens做判断；无信源的结论标记为"需人工验证"，不进入Expert Lens。

#### 3.0.2 事实核查网关的操作流程

```
对Analysis Agent产出的每个关键结论：
  │
  ├─ Step 1: 提取关键事实性断言
  │   └─ 识别结论中可验证的事实性陈述（如数据、事件、关系）
  │
  ├─ Step 2: 联网搜索
  │   └─ 对每个事实性断言，构造搜索查询，执行搜索
  │
  ├─ Step 3: 交叉验证
  │   └─ 多信源比对：至少2个独立信源确认，或1个权威信源确认
  │
  ├─ Step 4: 标注信源
  │   └─ 每个结论标注：信源URL+日期+摘要+验证状态
  │
  └─ Step 5: 分类输出
      ├─ ✅ 有信源支撑 → 进入Expert Lens
      ├─ ⚠️ 信源矛盾 → 标记分歧，进入Expert Lens但标注"信源矛盾"
      └─ ❌ 无信源 → 标记"需人工验证"，不进入Expert Lens
```

#### 3.0.3 事实核查网关的输出格式

| 结论 | 搜索查询 | 信源1 | 信源2 | 验证状态 | 后续处理 |
|:---|:---|:---|:---|:---|:---|
| 中石化与宁德签1万座换电合作 | "中石化 宁德时代 换电 合作" | 财联社 2025-03-15 | 新华网 2025-03-16 | ✅ 有信源支撑 | 进入Expert Lens |
| 中石化与比亚迪签2万座换电合作 | "中石化 比亚迪 换电 合作 2026" | 证券时报 2026-06-10 | — | ✅ 有信源支撑 | 进入Expert Lens |
| 华为"不排斥"策略削弱宁德议价力 | "华为 换电 不排斥 策略" | 36氪 2025-08 | — | ⚠️ 间接支撑 | 进入Expert Lens，标注"间接推理" |
| 某车企内部讨论加入换电联盟 | — | — | — | ❌ 无信源 | 需人工验证 |

### 3.1 问题：Agent的判断力从哪来？

传统观点认为Agent只能做信息搜集和模板化输出，判断力必须靠人工。但实际写作经验表明，很多"判断"并非原创洞察，而是**已有智慧的重新组合**：

- "比亚迪封闭生态是结构性挤压"——这是波特五力分析的直接应用
- "华为'不排斥'策略最危险"——这是纳什均衡的推论
- "关联交易抵消是相变期生死问题"——这是财务分析的基本功
- "中石化双下注削弱宁德议价力"——这是通过搜索公开新闻得出的（2025年中石化与宁德签1万座合作，2026年6月又与比亚迪签2万座合作，联网搜索即可发现）

**关键洞察**：大部分"判断"不需要原创智慧，而是需要**正确的分析框架+充分的信息**。Agent如果能：
1. 用联网搜索获取充分信息（竞争动态、合作签约、政策变化等均可自动发现）
2. 用多个专家视角分别审视（学者+企业家+投资人+技术专家，覆盖商业判断的各个维度）
3. 综合给出基础意见

那么Agent的判断力可以达到**普通人类分析师90%以上水平**，人工只需在此基础上做最后的行业专识校准。

**为什么专家视角模拟可以达到90%以上水平？**

人类分析师的"判断力"本质上来自三个层次：
1. **通用方法论**（占比~60%）：五力分析、纳什均衡、颠覆式创新、第一性原理等——这些已被学者系统化，Agent可直接调用
2. **跨领域经验**（占比~25%）：企业家和投资人的实战智慧——马斯克的第一性原理、巴菲特的现金流思维、李录的能力圈——这些虽非系统理论，但已有大量公开论述，Agent可模拟其视角
3. **行业专识**（占比~15%）：特定行业的非公开信息、独到认知——如"某车企内部正在讨论加入换电联盟"——这是Agent无法获取的，也是人工介入的核心价值

因此，Agent通过专家视角模拟可覆盖前两个层次（85%），加上联网搜索的信息补充（再+5%），综合可达90%以上。人工仅在第3层次介入，效果远优于"从零开始人工判断"。

**人工介入的正确方式：不是替代Agent判断，而是在Agent判断基础上校准**

传统思路是"Agent做不了判断→人工来做"，但更高效的方式是：
1. Agent先用专家视角给出基础判断（已达到90%水平）
2. 人工在基础判断上做行业专识校准（补充那15%的非公开信息/独到认知）
3. 校准后的判断 = Agent基础判断 + 人工增量 = 远超单靠人工的判断质量

这种方式的好处：人工不需要从零开始思考，而是在高质量基础上做增量，效率大幅提升。

### 3.2 专家视角模拟的设计

**Expert Lens Agent**在Fact-Check Gateway通过后，对"有信源支撑"的结论自动用以下视角分别审视。视角选取覆盖**学者、技术专家、企业家、投资人**四类，确保商业判断的各个维度都有覆盖：

| 视角类别 | 代表人物 | 审视重点 | 输出 |
|:---|:---|:---|:---|
| **战略学者** | 迈克尔·波特 | 竞争格局是否用五力分析到位？护城河是否可持续？ | 战略视角评审意见 |
| **博弈论学者** | 约翰·纳什 / 冯·诺依曼 | 合作方博弈是否找到均衡点？是否有被忽略的博弈方？零和博弈还是正和博弈？ | 博弈视角评审意见 |
| **创新理论学者** | 克莱顿·克里斯坦森 | 颠覆式创新检验是否到位？是否从低端向上生长？ | 创新视角评审意见 |
| **技术专家** | 曾毓群 / 王传福 | 电池技术路线判断是否准确？固态电池/超充对换电的替代威胁是否被低估？ | 技术视角评审意见 |
| **企业家** | 埃隆·马斯克 / 任正非 | 第一性原理是否到位？是否有更简单的解法？执行力瓶颈在哪？ | 实战视角评审意见 |
| **投资人** | 沃伦·巴菲特 / 李录 | IRR是否真实？现金流是否可持续？能力圈是否诚实？安全边际是否足够？ | 投资视角评审意见 |

> **设计原则**：选取的专家必须满足两个条件——①其方法论/思维框架已被系统化并有大量公开论述（Agent可模拟）②其视角与当前分析维度高度相关（不是随机选人）。每类视角至少1人，最多3人，避免视角过多导致综合意见失焦。

**综合意见生成规则**：
1. 每个视角独立给出"同意/有保留/反对"+理由+**引用的具体信源**
2. 统计各视角的一致度——如果6个视角中≥5个同意，则结论置信度高
3. 如果有≥2个视角"反对"，则标记为"需人工重点审核"
4. 最终输出：综合意见+分歧点+信源清单+人工审核建议
5. **人工校准流程**：Agent先给出基础判断（已达到90%水平）→ 人工在基础判断上做行业专识校准（补充非公开信息/独到认知）→ 校准后形成最终判断
6. **无信源结论处理**：Fact-Check Gateway标记为"需人工验证"的结论，不进入Expert Lens，直接进入人工审核队列

### 3.3 专家视角模拟的效果预估

| 场景 | 无专家视角 | 有专家视角 | 人工介入需求 |
|:---|:---|:---|:---|
| 竞争格局判断 | Agent只能罗列信息 | 波特视角自动做五力分析，纳什视角自动找均衡 | 从40%降至15% |
| 博弈推理 | Agent只能列合作方信息 | 纳什视角做均衡分析，巴菲特视角看现金流博弈 | 从50%降至20% |
| 财务判断 | Agent能算IRR | 巴菲特视角检查现金流真实性，李录视角检查安全边际 | 从15%降至5% |
| 战略洞察 | Agent做不出来 | 克里斯坦森视角做颠覆检验，马斯克视角做第一性原理 | 从70%降至30% |

## 四、修正后的自动化率评估

### 4.1 逐环节自动化率（V3修正）

| 环节 | V2自动化率 | V3自动化率 | 修正理由 |
|:---|:---:|:---:|:---|
| **L1 问题界定** | 80% | **85%** | Q6框架可模板化，维度触及矩阵模板化后可自动生成 |
| **L2 需求原点+嵌套课题+维度触及矩阵** | 88% | **90%** | 维度触及矩阵可自动生成（嵌套课题→后续层维度映射），引用+补全机制模板化 |
| **L3 产业结构分析** | 85% | **88%** | 引用L2已覆盖部分+补全未覆盖部分，减少重复分析；Fact-Check Gateway自动搜索竞争动态 |
| **L4 战略必要性分析** | 78% | **82%** | 引用+补全机制减少重复；Fact-Check Gateway自动搜索威胁信息 |
| **L5 能力圈与财务** | 85% | **88%** | 引用+补全机制；财务模型模板化程度高 |
| **L6 合作方博弈分析** | 80% | **85%** | 引用+补全机制；Fact-Check Gateway自动搜索合作动态+纳什视角自动做均衡 |
| **L7 终局判断（含执行配套）** | 72% | **75%** | 底线条件清单可从各层汇总；执行配套（监测指标+姿态触发条件）可模板化 |
| **Fact-Check Gateway** | — | **95%** | 搜索+交叉验证+标注信源，高度自动化，仅信源矛盾时需人工判断 |
| **CQ诊断** | 70% | **75%** | 逻辑一致性+数据溯源可自动化，维度触及矩阵提供额外一致性校验维度 |
| **报告编译** | 90% | **92%** | 引用+补全机制使跨章引用更规范，模板化程度更高 |

> **V2修正的核心逻辑**：
> - **需求验证**：V1认为30%需人工介入（访谈+一手数据解读），V2修正为12%——Agent自动生成访谈对象清单和数据需求清单，人工只需做少量一手数据解读校准
> - **产业结构**：V1认为40%需人工介入（竞争动态判断），V2修正为15%——中石化双下注等竞争动态完全可通过联网搜索自动发现，五力分析由波特视角自动执行
> - **博弈分析**：V1认为50%需人工介入（合作方真实意图判断），V2修正为20%——Agent先用6类专家视角综合给出基础判断（达90%水平），人工仅做行业专识的最终校准
> **V3修正的核心逻辑**：
> - **维度触及矩阵+引用补全**：V2没有这个机制，L2嵌套课题与后续层之间存在重复分析或遗漏。V3通过维度触及矩阵明确"哪些已覆盖、哪些未覆盖"，后续层引用已覆盖部分、只补全未覆盖部分，减少重复、避免遗漏
> - **事实核查网关**：V2的Expert Lens直接对结论做判断，存在幻觉风险。V3在Expert Lens前插入Fact-Check Gateway，确保判断基于信源，消除幻觉
> - **删除L5/L7独立层**：V2有9层（L-1到L7），V3精简为7层（L1-L7），与共振gemini对齐，减少不必要的层间跳转

### 4.2 总体自动化率

| 指标 | V1 | V2 | V3 |
|:---|:---:|:---:|:---:|
| 总体自动化率 | ~60% | ~80% | **~85%** |
| 需人工介入比例 | ~40% | ~20% | **~15%** |
| 人工介入类型 | 判断+推理+校准 | 仅行业专识校准 | **仅行业专识校准+无信源结论验证** |

### 4.3 人工介入的重新定义

V1认为人工需要做"判断"和"推理"，V2修正为"行业专识校准"，V3进一步细化：

| 人工介入类型 | V1占比 | V2占比 | V3占比 | 说明 |
|:---|:---:|:---:|:---:|:---|
| **行业专识校准** | 15% | 12% | 10% | Agent无法获取的非公开信息或独到行业认知（如"某车企内部正在讨论加入换电联盟"）。Agent已给出基础判断，人工只需做增量校准 |
| **无信源结论验证** | — | — | 3% | Fact-Check Gateway标记为"无信源"的结论，需人工通过访谈/渠道验证 |
| **推理/判断** | 15% | 3% | 2% | 大部分推理可由专家视角模拟覆盖，仅极少数原创洞察需人工 |
| **信息搜集** | 5% | 0% | 0% | Fact-Check Gateway自动搜索+交叉验证 |
| **模板化输出** | 5% | 0% | 0% | 完全自动化 |
| **一致性检查** | 5% | 2% | 0% | 维度触及矩阵+引用补全机制可自动检测跨层一致性 |

> **关键变化**：V2的核心转变是"人工介入方式"从"替代Agent做判断"变为"在Agent基础判断上做增量校准"。Agent先用专家视角给出90%水平的基础判断，人工只需补充那10-15%的行业专识，效率大幅提升。
> **V3关键变化**：维度触及矩阵+引用补全机制消除了跨层一致性的人工检查需求；Fact-Check Gateway将"信息搜集"完全自动化，但引入了"无信源结论验证"这一新的人工介入类型。

## 五、Agent做不到的三件事（V3修正）

### 5.1 仍然做不到的

1. **原创洞察**——"换电在营运车场景的隐藏频率尚未被充分定价"——这种洞察是信息+判断力的涌现，专家视角模拟可以逼近但无法原创。Agent能做的是"用克里斯坦森视角发现颠覆式创新特征"，但不能发现"隐藏频率"这个概念本身。

2. **元认知**——"换电站+电池银行不能分开算"——这是对问题结构的重新认知。Agent目前做不到"发现自己之前的框架有问题然后重构"。但可以通过Quality Gate Agent的CQ诊断触发人工审核，由人工决定是否重构。

3. **非公开信息**——车企内部决策、合作方真实意图、监管层私下态度——这些信息不在公开域，Agent无法获取。但Agent可以**标注信息缺口**，提示人工需要通过访谈/渠道获取。

### 5.2 V2认为做不到但V3认为可以做到的

| V2判断 | V3修正 | 机制 |
|:---|:---|:---|
| 竞争动态判断需人工 | **Fact-Check Gateway+专家视角可自动** | 搜索自动发现竞争动态，Fact-Check Gateway交叉验证，波特视角自动分析竞争格局 |
| 博弈推理需人工 | **纳什视角+专家视角+信源可给出基础判断** | Agent先用博弈论框架做均衡分析，Fact-Check Gateway验证前提，再用多位专家视角综合 |
| 跨章一致性需人工 | **维度触及矩阵+引用补全可自动检测** | 维度触及矩阵明确每层覆盖范围，引用补全机制自动检测重复和遗漏 |
| Expert Lens幻觉风险 | **Fact-Check Gateway前置消除** | 搜索→交叉验证→标注信源，Expert Lens只在信源基础上做判断 |

## 六、每个Agent的Skill构成

每个Agent需要3类知识才能自动化：

| 知识类型 | 内容 | 来源 | 实现方式 |
|:---|:---|:---|:---|
| **方法论** | 分析框架、推理规则、判断标准 | 七层框架V3+共振方法论（合并文件） | Skill的系统提示词 |
| **提问清单** | 每层该问什么、怎么问、追问逻辑 | Q6要素重构+问答记录 | Skill的工具/模板 |
| **经验教训** | 常见错误、易跳步骤、易忽略维度 | 历次分析的教训清单 | Skill的校验规则 |
| **维度触及矩阵** | 嵌套课题与后续层的覆盖关系 | L2嵌套课题产出 | 引用+补全声明模板 |

### 6.6 Fact-Check Gateway的Skill

```
输入：Analysis Agent产出的关键结论

输出：
  - 信源验证表（每个结论的验证状态+信源清单）
  - ✅ 有信源支撑的结论清单 → 进入Expert Lens
  - ⚠️ 信源矛盾的结论清单 → 进入Expert Lens但标注"信源矛盾"
  - ❌ 无信源的结论清单 → 进入人工审核队列
```

```

输出：
  - 完整报告（7章+附录）
  - 交叉引用索引
  - 信源清单（所有Fact-Check Gateway验证过的信源）
  - 一致性检查报告
```

### 6.8 Quality Gate Agent的Skill

```
输入：每步产出+维度触及矩阵

  - 逻辑一致性校验
  - 数据溯源检查
  - 信息源多元度评估
  - ★ 维度触及矩阵校验（检查引用声明是否与矩阵一致）

  - CQ诊断报告
  - 逻辑矛盾清单
  - 数据缺口清单
  - ★ 维度覆盖完整性报告（哪些维度已覆盖、哪些遗漏）

```

## 七、执行流程：3步自动化

### 7.1 Step 1: 提问（Question Agent）

```
用户输入："分析宁德时代换电业务的最优共振姿态"
    ↓
Question Agent：
  1. 识别决策类型（光谱选择：试点/卡位/霸主）
  2. 按Q6框架生成结构化问题清单
  3. 识别嵌套课题（电池标准化/车企适配/经济可行性）
  4. 生成数据需求清单（搜索/访谈/建模）
  5. 生成访谈对象建议清单
    ↓
输出：问题清单+嵌套课题+数据需求+访谈建议
人工审核：确认问题清单完整性（5分钟）
```

### 7.2 Step 2: 回答（Analysis Agents + Fact-Check Gateway + Expert Lens Agent）

```
Question Agent输出
    ↓
并行执行：
  ├─ Demand Verification Agent → 需求验证结论+维度触及矩阵
  ├─ Industry Analysis Agent → 产业结构+战略必要性结论（引用+补全）
  ├─ Financial Agent → 能力圈+财务精算结论（引用+补全）
  └─ Game Theory Agent → 合作方博弈结论（引用+补全）
    ↓
Fact-Check Gateway（对每个Agent的关键结论做事实核查）：
  ├─ 提取事实性断言
  ├─ 联网搜索+交叉验证
  ├─ 标注信源+分类输出
  └─ ✅有信源 / ⚠️信源矛盾 / ❌无信源
    ↓
Expert Lens Agent（只对✅和⚠️的结论做专家视角审视）：
  ├─ 波特视角 → 战略评审意见（引用信源）
  ├─ 纳什视角 → 博弈评审意见（引用信源）
  ├─ 克里斯坦森视角 → 创新评审意见（引用信源）
  ├─ 巴菲特视角 → 财务评审意见（引用信源）
  ├─ 马斯克视角 → 实战评审意见（引用信源）
  └─ 李录视角 → 投资评审意见（引用信源）
    ↓
Quality Gate Agent（CQ诊断+维度触及矩阵校验）：
  ├─ 逻辑一致性检查
  ├─ 数据溯源检查
  ├─ 跨章矛盾检测
  └─ 维度覆盖完整性检查
    ↓
输出：各层分析结论+信源清单+专家综合意见+分歧点+人工审核建议
人工审核：①校准专家视角分歧点 ②补充非公开信息 ③验证无信源结论（30-60分钟）
```

### 7.3 Step 3: 整合（Report Agent）

```
所有分析结论+人工校准
    ↓
Report Agent：
  1. 按7章模板（L1-L7）编译完整报告
  2. 生成交叉引用索引（基于维度触及矩阵）
  3. 生成附录（论证过程+批判追问+信源清单）
  4. 一致性校验
    ↓
Quality Gate Agent（最终CQ诊断）
    ↓
输出：完整报告+一致性检查报告
人工审核：叙事节奏+最终校准（15-30分钟）
```

```
过程中（Agent工作态）：
```

- 但中间产物应保留（作为审计轨迹+经验教训来源）

## 九、维度触及矩阵+引用补全机制

### 9.1 问题：L2嵌套课题与后续层的交叉轮回

L2需求原点的Q6第四层追问（嵌套课题识别）会触及后续L3-L6的部分内容。以宁德时代换电业务为例：

- 嵌套课题"电池标准化"触及了L3产业结构（竞争格局）、L4战略必要性（车企视角）、L5能力圈（技术能力）、L6合作方博弈（车企适配动机）
- 嵌套课题"经济可行性"触及了L5能力圈（财务精算）、L6合作方博弈（运营方动机）

这导致一个困境：在L2做需求分析时，就已经在触及后续层的内容；但后续层又不是完整地做，只是部分触及。如果不管理这种交叉，就会导致重复分析或遗漏。

### 9.2 解决方案：维度触及矩阵

L2的Q6第四层追问产出一份**维度触及矩阵**，明确每个嵌套课题触及了后续哪些层、哪些维度、覆盖程度如何：

```
               课题1        课题2        课题3
   L3 产业结构 │  ✓竞争格局  │  ✓利润分配  │             │
   L4 战略紧迫 │             │  部分       │             │
   L5 能力圈   │             │             │  部分财务    │
   L6 合作方   │  ✓车企适配  │  部分运营   │  部分资本    │
   L7 终局     │             │             │             │
```

### 9.3 引用+补全机制

后续层（L3-L6）在开始分析时，先声明引用L2已覆盖的部分，只补全未覆盖的部分：

> **引用声明格式**：【引用L2嵌套课题X结论】竞争格局部分详见课题X验证结果。本章补全：产业链利润分配、护城河可持续性分析。

**避免重复的checklist**：
- [ ] L3-L6每章开头是否有引用声明？
- [ ] 引用声明是否与维度触及矩阵一致？
- [ ] 补全内容是否确实是矩阵中标记为"未覆盖"的维度？
- [ ] 是否有维度被遗漏（矩阵中标记为"触及"但既未引用也未补全）？

### 9.4 写作流程

```
阶段1：L1 问题界定
阶段2：L2 需求原点（含Q1-Q7+嵌套课题深挖）→ 产出维度触及矩阵
阶段3：并行写L3-L6（维度补全）→ 每层引用声明+补全未覆盖部分
阶段4：L7 终局判断（含执行配套）
阶段5：Quality Gate Agent全局CQ诊断+维度覆盖完整性检查
```

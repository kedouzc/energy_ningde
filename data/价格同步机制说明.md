# 电池价格「单一数据源」同步机制

## 解决什么问题

之前价格手册（`.md`）改了初始价 / 年降率，下游要手动逐个改 `constants.js`、`batteryBank.js`、`manufacturing.js`、`model.html`、毛估估文档——漏改就错。

现在：**`.md` 是唯一录入口（自变量），`.js` 解析并推导因变量，一条命令全链路同步。**

## 数据流向

```
              自变量（人改，只在这）
   电池价格口径统一与pack价格参考.md
   ├─ Y0 行：电芯/加成/毛利初始值
   ├─ §3.2 三阶段变化率（平台±1.3% → 缓降-4% → 慢降-2.75%/年）
   └─ 锚点：加成/毛利 Y0→Y15 线性端点
            │  parseMD() 解析自变量
            ▼
   battery_prices.js  ── 推导 15 年因变量（应变量由 js 算）
   ├─ 动力/储能电芯、Pack加成、毛利逐年序列（三阶段分段累积）
   ├─ Pack裸/含税/售价、市场pack、换电结算价、单块成本
   └─ 折扣序列（相对 Y0，毛估估折扣链用）
            │  sync_prices.js 一键同步
            ▼
   ┌─────────────────────────────────────────────┐
   │ 1. 手册 §3.2.1/§3.2.2 表格      ← 回填（展示） │
   │ 2. 财务模型 engine/constants.js  ← AUTO-GEN 区 │
   │    （POWER_CELL_BY_YEAR / ESS_CELL_BY_YEAR /   │
   │     BAT_PRICE_BY_YEAR / getBatteryPriceByYear）│
   │ 3. 毛估估文档 §一/§三 折扣链    ← 三阶段重算   │
   │ 4. 毛估估文档 总表 (g)→⑤       ← 联动重算      │
   └─────────────────────────────────────────────┘
```

## 用法

改了 `.md` 里的初始价 / 三阶段 / 锚点后，运行任意一条：

- **双击** `data/sync_prices.bat`
- 或命令行：`node 宁德时代/data/sync_prices.js`（cwd 需能进入中文目录；若中文路径乱码，用 `data/sync_prices.bat` 或在本文件同目录跑 `node sync_prices.js`）

首次运行会在 `constants.js` 注入 `AUTO-GEN` 区、回填手册表格、改写毛估估折扣链与总表。后续运行自动覆盖更新。

## 关键约定

- **`.js` 不存任何价格数字**：`battery_prices.js` 只解析 `.md` 自变量并推导。改价格**只改 `.md`**，绝不直接改 `.js`。
- `constants.js` 的 `AUTO-GEN: PRICE SECTION` 区由脚本生成，**手工修改会被下次同步覆盖**——请改 `.md`。
- 毛估估文档的 `AUTO-GEN` / 整体折扣链段同理。
- 三阶段与手册表格的常年偏差 <0.2%（仅四舍五入），量级自洽。

## 维护触发条件（什么情况要回来改 sync_prices.js）

本机制把"易变的下钻注入"和"稳定的核心推导"分开：**`battery_prices.js`（解析+推导）几乎不用动**；只有 `sync_prices.js` 的"注入下游"部分会随下游变化而需维护。出现以下任一种情况，才需要改 `sync_prices.js`，且改法都局限在明确位置：

| 触发情形 | 改哪里（sync_prices.js） | 改什么 |
|---|---|---|
| **下游文件挪目录 / 改名** | 顶部 `TARGETS` 配置块（约 L27-40） | 只改对应路径字符串，不动函数体 |
| **毛估估 md 改了 `## 一` / `## 三` 章节标题或表格列结构** | `syncSwapDoc()` 内的正则：`## 一` 段 L211、`寿命 3.8 年` 城配表 L229、说明段 L232-244 | 同步调整正则，使锚点仍能被匹配 |
| **毛估估 md 总表 `(g)→⑤` 段改了表头/列** | `syncTotalTable()` 末行正则 L372 | 调整 `(g)→⑤` 的匹配区间 |
| **新增第 N 个消费价格数据的文件**（如新业务线也用电池价） | 新增一个 `syncXxx()` 函数，并在文件末尾主流程（L378-381）加一行调用 | 复用 `P.fromMarkdown` 的 `D` 序列，不要在新函数里写死价格数字 |
| **价格手册 md 改了 §3.2.1/§3.2.2 的"口径定义"**（如列含义、Y0/Y15 锚点位置） | `battery_prices.js` 的 `parseMD()`（解析自变量） | 仅当口径语义变才动；纯数值变动不改这里 |

> 经验法则：**只改价格数字 → 永远只动 `电池价格口径统一与pack价格参考.md`，跑脚本即可；动结构/增下游 → 才碰 `sync_prices.js`**。绝不在 `sync_prices.js` 里手填价格数字（那会破坏单一数据源）。

## 文件清单

| 文件 | 角色 |
|---|---|
| `电池价格口径统一与pack价格参考.md` | **唯一录入口**（自变量） |
| `battery_prices.js` | 解析器 + 推导器（真源逻辑） |
| `sync_prices.js` | 同步器（解析→推导→注入下游） |
| `sync_prices.bat` | 一键启动 |
| `财务模型/engine/constants.js` | AUTO-GEN 价格数组（下游消费） |
| `财务模型/engine/batteryBank.js` `manufacturing.js` | 查三阶段数组（已去 v1.0 残留） |
| `分析结论/换电毛估估_折扣链与总表.md` | 折扣链 + 总表（自动联动） |

```js
const P = require('./battery_prices.js');
const md = fs.readFileSync('电池价格口径统一与pack价格参考.md','utf8');
const {S,D} = P.fromMarkdown(md);
// D.powerTax / D.blockSettle / D.discPower 即 15 年因变量
// 折扣链：P.discountAt(D, 5.7, 'power') 等
```

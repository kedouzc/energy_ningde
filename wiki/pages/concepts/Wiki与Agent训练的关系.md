# Wiki与Agent训练的关系

> **定义**：分析DNA双螺旋知识库在"训练懂用户思维的Agent"这个终极目标中的定位  
> **状态**：架构设计中（持续演化，4-11新增THINKING_PATH机制后已从纯理论进入可操作阶段）  
> **核心结论**：Wiki是训练数据的**源头**，但不是训练数据的**载体**；Raw层可通过THINKING_PATH机制主动嵌入机器可读标注，Wiki层保持可读格式不变（分层不变形原则）

---

## 背景（来自问题原点）

```
底层信念：投资和人生决策共享同一套方法论
    │
    ├── 投资的本质 = 在不确定性下分配稀缺资源
    │     ├── 金钱（证券市场）        ← Wiki当前主要场景
    │     ├── 时间（职业/学习方向）   ← 同一套方法论适用
    │     ├── 精力（关系/项目选择）   ← 同一套方法论适用
    │     └── 注意力（每天的选择）    ← 同一套方法论适用
    │
    └── 投资时间和精力 > 投资金钱
          （因为时间不可再生，精力有限）
          所以人生决策是比金融投资更根本的投资

终极目标：形成这套统一的方法论，让AI能辅助所有类型的"投资决策"
    ↓
中间目标：在探索过程中让AI越来越懂用户的思维模式
    ↓
最终愿景：训练一个应用统一方法论的Agent
         （不存在"非投资应用域"——所有决策都是投资决策）
```

## 三层能力模型

Wiki能服务的是三个不同层次的目标：

| 层次 | 目标 | 所需数据类型 | Wiki能提供？ | 当前状态 |
|------|------|------------|-------------|---------|
| **L1 知识复用** | "回答问题时基于全部知识" | 事实+概念+关联 | ✅ **完美胜任** | 已实现（Query流程） |
| **L2a 已声明模式适配** | "LLM适配用户已识别的思维模式" | **认知风格声明**（System Prompt） | ✅ **可直接声明实现** | ✅ 已完成（CLAUDE.md v2.3认知画像，2个已声明模式） |
| **L2b-1 未声明模式发掘** | "发现用户尚未识别的思维模式" | 从叙事记录中统计/模式识别 | 🔄 **部分提供（轨道2演化记录+DNA_Logs）** | 🔄 持续进行，依赖样本积累 |
| **L2b-2 结构化数据积累** | "为未来Agent训练准备结构化数据" | 推理链+偏好+决策的结构化记录 | 🔄 **THINKING_PATH(已声明)+待扩展(未声明)** | 🔄 进行中 |
| **L3 Agent迁移** | "训练独立应用统一方法论的Agent" | 结构化训练集（IO对+奖励信号） | ❌ **不是为这个设计的** | ⏳ 待阶段2启动 |

### 关键修订：L2 的三层结构

4-10版本将L2统一标记为"⚠️ 部分提供"。4-11首次修订将其拆为L2a(声明)和L2b(积累)，但这个拆分仍然隐含一个**过度乐观的假设**——认为已声明的2个模式就代表了用户的完整思维结构。

实际情况更准确的表达是：

```
┌─────────────────────────────────────────────────┐
│              用户思维模式的完整图景               │
│                                                   │
│  ┌───────────────────┐                          │
│  │ 已声明模式（已知）  │ ← 层层深挖 + 跨域锚定    │
│  │   数量：2个        │ ← 可通过System Prompt声明  │
│  │   状态：✅ L2a解决  │ ← THINKING_PATH可结构化   │
│  └───────────────────┘                          │
│                                                   │
│  ┌───────────────────┐                          │
│  │ 未声明模式（未知）  │ ← 用户自己也不知道有哪些  │
│  │   数量：???        │ ← 藏在叙事文字的行为模式中 │
│  │   状态：🔄 需要发掘 │ ← 需要从记录中AI统计发现   │
│  └───────────────────┘                          │
│                                                   │
│  核心修正：THINKING_PATH只覆盖"已声明"部分的      │
│  结构化记录。"未声明"部分仍需原始4-10版本中的     │
│  "从叙事中提取"路径。两者并行，不可替代。          │
└─────────────────────────────────────────────────┘
```

**所以原来的"⚠️ 部分提供"判断并没有过时**——它描述的正是L2b-1（未声明模式发掘）的空间。4-11的新增是L2a（已声明模式的快速通道），而不是对L2b-1的替代。

### L1：Wiki的核心功能（已实现）

```
用户提问："宁德时代的壁垒是什么？"
    ↓
LLM读index → 定位[四层框架]+[宁德时代]实体页 → 综合回答
    ↓
产出：带引用的、基于全部知识库的答案
```

这正是Karpathy原文定义的全部范围。

### L2a：已声明模式 → System Prompt（✅ 已完成）

**内容**：当前已识别并显式编码的2个思维模式：
1. **层层深挖**（4条已知链条，每条有明确的层级结构）
2. **跨域锚定**（6类连接类型，有优先级排序）

**实现方式**：直接写入CLAUDE.md作为System Prompt，当前会话LLM读取即可适配。无需训练数据。

详细规范见：[CLAUDE.md 轨道2「用户认知风格画像」](../../CLAUDE.md#L396-L442)

**局限性**：只覆盖用户**已经意识到并能描述**的思维模式。用户可能还有自己未曾留意的习惯性模式（例如：某些情况下倾向于冒险、某些隐喻反复出现等），这些属于L2b-1的范围。

### L2b-1：未声明模式 → AI发掘（🔄 持续进行）

**问题**：用户有一些思维模式特征，自己还没有意识到，因此无法主动声明。但这些模式可能规律性地出现在：
- 轨道2协作记录中的决策选择倾向
- DNA_Logs演化过程中的方向偏好
- 对🔴🟡🟢三类建议的反应模式

**方法**：当积累了足够多的叙事记录后（目标：DNA_Logs超过20条 + 轨道2建议反馈超过50条），可以尝试用LLM做模式识别分析，发现潜在的思维特征，再由用户确认是否纳入L2a的声明集合。

**与4-10原版的关系**：这就是原版"L2: ⚠️ 部分提供"所描述的空间。它没有被THINKING_PATH替代，而是作为一条独立的、长期的路径存在。

### L2b-2：结构化数据积累（🔄 进行中）

无论模式是已声明还是未声明，训练Agent最终都需要结构化数据。THINKING_PATH机制负责已声明部分的结构化；未声明部分的结构化有待L2b-1发现后再补充。

详见下文「THINKING_PATH机制」章节。

### L3：独立Agent——应用统一方法论（⏳ 待启动）

> **重要修正**：L3的训练目标场景**不是**"非投资应用域"。投资和人生决策共享同一套底层方法论——都是在不确定性下分配稀缺资源。金钱只是其中一种资源；时间、精力、注意力是更根本的投资标的。详见下文「统一方法论」章节。

## THINKING_PATH机制（4-11新增）

> **定义**：在Raw层（投研层`框架/`）的markdown文件中，由LLM自动附加机器可读的思维路径标签（HTML注释形式）
> **目标**：在不改变用户写作习惯和不影响人眼阅读的前提下，让文档自然积累"思考路径"的结构化数据
> **来源**：2026-04-11 跨域同构发现后的元认知反思
> **详细规范**：[CLAUDE.md#L463-L530](../CLAUDE.md#L463-L530)

### 核心设计原则

| 原则 | 说明 |
|------|------|
| **对人不可见** | 使用HTML注释 `<!-- -->` 嵌入，markdown渲染时自动隐藏 |
| **对机器可解析** | 标准JSON格式，可用脚本批量提取 |
| **不改变正文** | 只追加在段落末尾，不修改任何已有内容 |
| **零用户负担** | 由LLM在写入时自动附加，用户感知不到额外步骤 |

### 首次应用示例

已在 `框架/2026-04-11_任务导向组织设计_投资映射.md` 中实际应用，共5个标注：

| 位置 | layer | operation | physics_anchor |
|------|-------|-----------|----------------|
| L1 观察段落后 | 1 | 观察 | null |
| L2 抽象段落后 | 2 | 概念修正 | null |
| L3 投资映射段落后 | 3 | 映射+验证 | ✅ 构造子理论 |
| L4 验证发散段落后 | 4 | 验证+发散 | null |
| 附录元认知段落后 | 0 | 元反思 | null |

## 数据格式差距（4-11修订版）

### 三种目标格式 vs 当前采集能力

| 维度 | Agent训练需要的格式 | THINKING_PATH能提供 | 轨道2能提供 | 缺口 |
|------|-------------------|------------------|-----------|------|
| **推理链** | `(问题, 追问序列, 最终答案)` 三元组 | ✅ `trigger`+`layer`+`output_concept` 可映射（需组装规则） | ⚠️ 部分覆盖 | 组装逻辑待定义 |
| **偏好** | `(AI建议, 接受/拒绝, 理由)` 偏好对 | ❌ 不覆盖 | ✅ 🔴🟡🟢三类建议追踪 | THINKING_PATH不涉及偏好 |
| **决策** | `(情境, 可选项, 选择, 结果)` 决策对 | ⚠️ `trigger`(≈情境) + `confidence`(≈选择置信度) | ⚠️ 部分覆盖 | 缺少"可选项"和"结果"字段 |

### 为什么不能直接只用Wiki文本做训练？（仍然成立，但已有缓解方案）

```
4-10时的状况：                    4-11后的状况：
                                 
Wiki文本 = 纯叙事                 Wiki文本 = 叙事 + 嵌入式JSON
    ↓                                ↓
问题1: 叙事缺乏结构化标注           ✅ THINKING_PATH提供了结构化标注
问题2: 缺乏IO对                     ⚠️ 部分解决（trigger≈输入, output≈输出）
问题3: 缺乏奖励信号                 ❌ 仍未解决（需要轨道2补充）
问题4: 事实和判断混杂               ⚠️ 部分解决（confidence字段区分置信度）
```

### THINKING_PATH → 训练格式的映射规则（待完善）

> **⚠️ 这是当前最关键的缺口**：THINKING_PATH定义了"怎么记录"，但还没有定义"如何转换为Agent训练所需的三种目标格式"。以下是初步映射框架，待阶段2实施时细化。

#### 推理链三元组的组装

```python
# 伪代码：从单个框架演化文件的多个THINKING_PATH标签组装推理链三元组
def assemble_reasoning_chain(file):
    paths = extract_all_thinking_paths(file)  # 按layer排序
    
    triplet = {
        "question": paths[0].trigger,                    # 初始触发问题
        "reasoning_sequence": [
            {
                "step": p.layer,
                "operation": p.operation,
                "input": p.trigger,
                "thinking": p.cross_domain_sources,      # 跨域联想过程
                "output": p.output_concept,               # 本层结论
                "framework": p.framework_used,
                "physics_anchor": p.physics_anchor,
            }
            for p in paths if p.layer > 0
        ],
        "final_answer": paths[-1].output_concept,         # 最终产出
        "meta_confidence": paths[-1].confidence,
    }
    return triplet
```

#### 偏好对的采集（PREFERENCE_PAIR标签——立即可用）

> **修正**：不再标记为"待设计"。从本次会话开始，每当轨道2产生🔴🟡🟢建议且用户做出反应时，LLM应在相关文件中附加PREFERENCE_PAIR标签。

**数据来源**：轨道2三类建议(🔴🟡🟢)的用户反馈记录

**触发条件**：
- LLM给出🔴/🟡/🟢三类建议后，用户明确表示接受、拒绝、搁置、展开或忽略
- 用户对LLM的某个判断提出异议或补充

**标签格式**：

```markdown
<!-- PREFERENCE_PAIR
{
  "timestamp": "ISO8601时间戳",
  "category": "must_have|should_have|nice_to_have",
  "suggestion": "LLM给出的具体建议内容",

```

**写入位置**：追加在轨道2产出的Wiki文件末尾（`pages/sources/` 或 `pages/AI_Logs/` 中），或在投研层 `框架/` 文件的讨论段落之后。

**首次应用目标**：在下次轨道2协作中遇到用户反馈时立即使用。

#### 决策对的采集（DECISION_POINT标签——立可用）

> **修正**：不再标记为"待选型"。当框架演化进入L4验证发散阶段或任何需要做选择的节点时，LLM应主动识别决策点并附加DECISION_POINT标签。

**THINKING_PATH现有字段 vs 决策对需要的字段**：

```
THINKING_PATH已有字段：            DECISION_POINT新增字段：
  trigger ≈ 决策情境 ✅             （复用trigger）
  (无)    ≠ 可选项 → options_list   ← 新增字段
  output_concept ≈ 选择 ⚠️          choice ← 可从output推断或显式声明
  confidence ≈ 选择置信度 ⚠️         （复用confidence）
  (无)    ≠ 结果 → outcome          ← 新增字段（可后续回填）
```

**标签格式**：

```markdown
<!-- DECISION_POINT
{
  "context": "决策情境描述（一句话）",
  "options": [
    {"label": "选项A", "description": "简要说明"},
    {"label": "选项B", "description": "简要说明"},
    {"label": "选项C", "description": "简要说明"}
  ],
  "choice": "用户选择的选项label",
  "rationale": "选择理由（用户原话摘录）",
  "confidence": "high|medium|low",
  "outcome": "选择后的实际结果（如已知则填写，否则写null）",
  "related_framework": "四层框架|投资原点|null"

```

**触发条件**：
- 框架演化文件的L4"待验证假设"段落后（假设本身就是一个决策点）
- 用户在多个方向之间做选择时
- 对🟡建议采取"去验证"行动后返回结果时

**写入位置**：紧跟在L4段落的THINKING_PATH标注之后。

### 关键原则

| 原则 | 4-10版本 | 4-11修订版 |
|------|---------|-----------|
| **分层不变形** | ~~Wiki不变形~~ | Wiki层（pages/）的可读格式不变；Raw层（投研层）可通过注释扩展机器可读标注 |
| **下游提取** | 训练数据集从Wiki中提取/衍生 | 不变，但提取难度因THINKING_PATH而降低 |
| **渐进结构化** | 先积累素材再考虑结构化 | **已开始主动结构化**（THINKING_PATH），不再被动等待 |
| **单一职责** | Wiki管L1+L2；训练集管L3 | 细化为：Wiki管L1+L2a；Raw层+轨道2管L2b数据采集；训练集管L3 |
| **开放-封闭原则** | （无） | **新增**：对扩展开放（加注释标签），对修改封闭（不改正文内容） |

### "Wiki不变形"→"分层不变形"的哲学转变

```
4-10的隐含假设：                    4-11的修正理解：
                                 
Wiki的读者 = 人类                  Wiki的读者 = 人类 + 机器
    ↓                                  ↓
格式必须服务于人类阅读              格式服务于多模态阅读
    ↓                                  ↓
任何改变都会损害可读性              不可见注释不影响可读性
    ↓                                  ↓
所以绝对不变形                      所以分层：可读层不变形，机器层可扩展

类比：                            类比：
纸质书不能改                       电子书可以加超链接
    ↓                               ↓
（但电子书的内容没变）              （内容没变，只是增加了索引）
    
THINKING_PATH就是给Wiki加的"超链接索引"
```

**LLM原版错误模型的隐含假设**：
- 把③当成层间过渡的**必经枢纽**——好像必须先批判完才能进入下一层
- 这等价于"先完整验证当前层才能往下挖"

**修正后的因果驱动模型**：

```
第N层：
  ① 【是什么】看到X
  ② 【为什么】问X的原因 → 得到Y
     └── Y = 第N+1层的①（自然的因果延续）
  ③ 【批判检验】——不是驱动引擎，而是质量分叉点
      ├── 通过 → 往下挖（以Y为起点）
      └── 发现漏洞 → 回头修（证伪→换路子）
```

**关于③的操作深度——LLM的分析（待用户判断）**：

LLM认为③虽然每层必做，但存在两种操作模式（不是"做不做"的问题，而是"做多深"的问题）：

| 模式 | 触发条件 | 操作方式 | 类比 |
|------|---------|---------|------|
| **A: 快速前提盘点** | **每层默认执行** | 列出本层②依赖的所有显性前提→可信度快速打分(高/中/低)→低分项标记为⚠️待验证项→不阻塞深挖 | 医生例行体检——每项都查到 |
| **B: 深度反事实审计** | 关键节点触发（锚点附近/重大决策/低分项堆积） | 对每个前提做完整反事实推理："如果这个前提不成立，整条链会怎样？"→可能触发回溯修正 | 专科深度诊断——异常项才深入 |

**关键设计**：模式A不是"浅尝辄止"，而是**高效全面覆盖+风险标记**。"待验证项"机制保证不遗漏可疑前提，同时不因每层都做深度审计而阻塞探索进度。

#### 结论1：递归模式的最终定义

```
层层深挖 = 因果追问链 + 每层质量分叉

第N层：
  ① 是什么？          （观察对象）
  ② 为什么？           （因果追问——答案Y = 第N+1层的①）
  ③ 批判检验（必做，但分两档）：
     ├── A档：快速前提盘点（每层默认）
     │   └── 列出前提 → 可信度打分 → ⚠️标记低分项 → 不阻塞
     └── B档：深度反事实审计（关键节点触发）
         └── "前提不成立会怎样？" → 可能回溯修正
          ↓
   分叉：③通过 → 第N+1层（以Y为新的①）
        ③发现问题 → 回到①或②修正
```

**与之前v2.3e初版的差异**：
- v2.3e初版：`基于第N层③的答案继续`（③=枢纽）
- v2.3e终版：`②的答案自然成为下一层的①`（②=驱动，③=分叉）

#### 结论2：层级A/B的正确定位

```
层级B（物理原语）= 正式符号系统 / 通用语言
  ├── 信息 → 量子场 → (物质 ⟷ 力) → 能量
  ├── 源于量子场论——描述宇宙基本组织方式
  ├── 跨领域统一命名，确保不同领域的映射可对齐
  └── 类比：化学元素周期表（H, He, Li...）

层级A（通俗描述）= 入门翻译 / 教学工具
  ├── 判断层 → 客观基底层 → (要素 ⟷ 机制)层 → 系统产出层
  ├── 帮助不熟悉物理的人快速理解每一层
  └── 最终目标：使用者直接用层级B思考
```

**四层框架的精确定位（替代原来L17的⚠️注意）**：
> 源于量子物理/量子信息学的通用底层认知框架。当前在投资领域已完成深层映射并作为核心分析方法；在商业/组织领域已初步验证；未来将扩展到人生决策、自我认知等领域。每个新领域都需要做独立的深层映射工作（不能照抄投资领域的映射结论），但框架本身的结构和类别命名是统一的。

## 二、DNA双螺旋工作流

### 核心机制

研究过程遵循**DNA双螺旋**结构：框架探索（左链）与问题涌现（右链）相互促进。

```
        框架探索（左链）              问题涌现（右链）
              │                            │
    ┌─────────┴─────────┐      ┌───────────┴───────────┐
    │ • 预设框架        │◄────►│ • 沿着框架问问题       │
    │ • 应用框架        │      │ • 发现新问题           │
    │ • 更新框架        │      │ • 追问问题             │
    └─────────┬─────────┘      └───────────┬───────────┘
              │                            │
              └────────────┬───────────────┘
                           │
                    ┌──────┴──────┐
                    │  交叉演化    │
                    │  （留痕）    │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        概念沉淀      案例积累      洞察生成
```

### 演化规律

| 规律 | 说明 |
|------|------|
| **问题驱动** | 所有演化都始于一个问题（苏格拉底式追问） |
| **涌现而非设计** | 四层框架是深挖时涌现的，不是预先设计的 |
| **双螺旋演化** | 框架探索 ↔ 问题涌现，相互促进 |
| **反哺完善** | 每个答案反哺框架，每个新问题驱动深挖 |

### 当前演化阶段

```

    ↓
能量信息框架v1（阶段1）
    ↓
四层框架发现（阶段2，关键突破）
```

## 三、设计约束

### 用户要求

1. **效率优先**：不要堆量，文件越少越好
2. **维护简单**：人类审核负担要小
3. **问题驱动**：从宁德时代入手，逐步抽象通用问题清单
4. **多AI验证**：同一问题交多个AI回答，交叉比对后蒸馏保留
5. **记录diff**：AI回答只记录变动部分

### Wiki设计原则

1. **过程优先**：记录"如何思考"比"思考结果"更重要
2. **双螺旋留痕**：框架探索 ↔ 问题涌现的每个交叉点都要记录
3. **AI蒸馏**：研报不存原文，只存AI提炼的精华+思维链
4. **最新框架可见**：一眼能看到当前在用哪个框架

### Karpathy精神

- **三层架构**：raw / wiki / schema
- **四个流程**：Ingest / Synthesize / Query / Lint
- **LLM维护wiki**，人类提供raw

### 知识传递的哲学基础：双模式认知

> **核心洞察**：知识传递存在"认知梯度"问题——专家与新手之间存在不可逾越的鸿沟。单一表达模式无法同时满足"直觉建立"和"精确理解"。这不是简化vs严谨的取舍，而是**两种互补的认知路径**。

#### 问题：为什么单一模式会失败？

| 模式 | 能做到 | 不能做到 | 失败场景 |
|------|-------|---------|---------|
| **纯专业术语** | 精确、严谨、可验证 | 无法建立直觉、门槛过高 | 新手看一眼就放弃 |
| **纯通俗类比** | 快速理解、降低门槛 | 可能误导、边界模糊 | 专家觉得太浅不信任 |

#### 洞察：两种模式的本质差异

```
📖 通俗版（直觉路径）          🔬 专业版（精确路径）
    │                              │
    ├── 目标：建立"感觉"           ├── 目标：建立"定义"
    ├── 方法：类比+故事            ├── 方法：公理+证明
    ├── 产出："啊，我懂了！"       ├── 产出："我知道边界在哪"
    └── 风险：可能过度简化         └── 风险：可能无法触达
```

**关键认识**：
- 这两种模式**不是同一事物的不同深度**，而是**两种不同的认知加工方式**
- 通俗版激活的是**右脑**（模式识别、类比思维）
- 专业版激活的是**左脑**（逻辑推理、精确分析）
- 两者需要**协同工作**，而非相互替代

#### 哲学根源：知识的双重性

**知识本身具有双重性**：

| 维度 | 隐性知识（Tacit） | 显性知识（Explicit） |
|------|------------------|---------------------|
| **来源** | 经验、直觉、实践 | 文本、公式、定义 |
| **传递方式** | 师徒制、模仿、沉浸 | 阅读、讲授、文档 |
| **特点** | 难以言说但深刻 | 易于传播但可能表面 |
| **对应模式** | 📖 通俗版（通过类比激活经验） | 🔬 专业版（通过定义明确边界） |

> **Polanyi悖论**："我们能知道的，多于我们能言说的。"  
> 通俗版的作用是**唤醒隐性知识**；专业版的作用是**固化显性知识**。

#### 对Wiki设计的指导意义

1. **每个概念页面必须同时提供两种模式**
   - 不是"先简后繁"的渐进式
   - 而是"双轨并行"的结构化呈现

2. **两种模式相互引用，而非孤立**
   - 通俗版可以提示"详见专业版的数学推导"
   - 专业版可以引用"回顾通俗版的直觉类比"

3. **质量检验的双重标准**
   - 通俗版检验：我妈能看懂吗？
   - 专业版检验：专家能认可吗？

4. **这不仅是写作规范，更是认知科学的应用**
   - 尊重人脑的信息处理机制
   - 降低知识传递中的信息损耗

## 四、Wiki定位

### 核心问题

> 如何记录"框架↔问题"DNA双螺旋演化过程？

### 目标

让思维链清晰可见，为AI训练积累路径数据。

### 作用

重构 `d:\AI\证券投资\投研` 的研究方式，直接形成：
1. **研究过程记录**（DNA双螺旋演化）
2. **成果积累**（框架、概念、案例）

Wiki的作用不是"记录你写了什么"，而是：
1. 促进投研深入（追问更深一层）
2. 促进发散探索（发现新的研究方向）
3. Wiki和投研交叉协作共同推进

**分工**：
- **投研/**：你的原始思考过程（你的领地，LLM只读）
- **Wiki/**：LLM从投研中提炼、整合、建立关联（LLM的领地）

**LLM行为准则**：
1. **Ingest**：读取投研/的原始文件，提炼到sources/或pages/
2. **不修改投研/**：LLM只读不写
3. **原子化**：每个独立研究对象一篇文件
4. **关联**：建立双向链接`[[页面名]]`

### AI训练价值

演化过程记录是训练AI理解用户思维方式的关键历史资料：
- 记录每版框架如何变化
- 记录问题如何驱动框架演化
- 记录交叉点如何产生洞察

AI通过阅读这些资料，能够：
1. 理解用户的探索路径
2. 顺着用户的思维过程给出新的启示
3. 成为真正懂用户的AI助手

## 五、操作流程：框架演化工作流

### 核心原则

> Wiki是框架实验室，不是档案馆。目标是辅助决策，不是完美记录。先用起来，在演化中完善。

### 三个时间尺度

#### 日常流程（研究新标的）

```
1. 发现新标的
   ↓
2. 在投研/下创建案例文件夹
   ↓
3. 用多个现有框架分别分析（创建分析文件）
   ↓
4. 对比哪个框架更适合这个标的
   ↓
5. 发现框架问题？→ 更新问题清单
   ↓
6. 产生新洞察？→ 记录到演化过程
   ↓
7. 触发Ingest → LLM提炼到Wiki
```

#### 每周流程（框架迭代）

```
每周固定时间做框架回顾（约30分钟）：
1. 回顾本周案例测试的发现
2. 更新框架演化路线图
3. 检查待解决问题进展
4. 推进关键决策点
5. 规划下周测试案例
```

#### 决策流程（关键节点）

```
当达到决策点时（如"统一框架 or 保持分立"）：
1. 汇总所有对比分析和案例测试结果
2. 用DNA双螺旋视角做决策分析（左链框架 vs 右链证据）
3. 更新框架演化路线图
4. 执行决策
5. 同步更新所有相关文档 + 触发Ingest
```

### 预期节奏

| 时间 | 预期成果 |
|------|---------|
| **1周后** | 当前在用框架清晰；至少1个案例完成多框架对比 |
| **1月后** | 测试3-5个等号公司；框架间关系图谱清晰 |
| **3月后** | 有明确的框架体系（统一or互补）；新标的可快速选框架 |

### 与Wiki的衔接点

每个时间尺度结束时，都应触发一次**Ingest**：

| 流程结束 | Ingest范围 | 写入位置 |
|---------|-----------|---------|
| 日常研究完一个标的 | 该标的的分析文件 | `pages/entities/` + `pages/sources/` |
| 每周回顾 | 本周所有变更 | `pages/DNA_Logs/` + `log.md` |
| 决策执行 | 决策相关的全部材料 | `pages/synthesis/` + `pages/DNA_Logs/` |

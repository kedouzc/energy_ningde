# 宁德时代投研报告 HTML 编写规则与教训

> 本文档记录在制作宁德时代投研报告 HTML（`宁德时代_V2.0.html`）过程中积累的基础规则、反复出现的问题和需要遵守的方法。
> 每次修改 HTML 前，请先过一遍本文档。

---

## 一、标题与文案

### 1.1 不引用内部文件名
- **禁止**：标题或正文中出现"PBL框架"、"来自XXX.md"、"第零层"、"问题一/二/三"等内部文档痕迹
- **正确**：直接用业务语言描述内容逻辑。例如 L1 标题写"逐层追问电池产业为什么不会消失"，然后直接在摘要里列 1.1~1.4 各层要解决的问题

### 1.2 不用"金句"等自我标榜词
- **禁止**：用"金句"、"名言"等标签
- **正确**：直接写"本质认知：……"即可

### 1.3 本质认知不独立成卡片
- 本质认知应当和该层的推导结论合在一起，形成"基于此认知→得出此结论"的完整链条
- 不要单独开一个卡片只放一句本质认知

### 1.4 专业术语要通俗化
- **禁止**：使用只有懂信息论+系统论才知道的术语（如"低熵格点"）
- **正确**：换成普通投资者能理解的语言（如"标准化能量载体"、"能量时空解耦介质"）
- 如果确有需要保留的专业术语，必须在附录C术语表中给出解释

### 1.5 摘要不讲该层不讨论的问题
- 每层摘要只写该层要回答的问题，不要把下层才讨论的结论提前放到这层摘要里
- 例如：1.1 讨论"为什么必须用电"，摘要里就不要写"电化学储能不是永续级"（那是 1.3 的问题）

### 1.6 标题和摘要必须直接给出结论，禁止思考痕迹
- **禁止**：标题写"范式切换：从必要到可行——为什么必须转 + 转了有什么好处 + 面临什么竞争"（这是思考维度，不是结论）
- **禁止**：摘要写"基于这个认知，2.1 从……推演，2.2 论证……，2.3 分析……"（这是写作提纲，不是给读者看的东西）
- **正确**：标题用关键词串联"现状→应对→核心能力"，让读者一眼就知道结论。如 L3 标题"制造承压 + 换电破局 + 流转基础设施是真正的护城河"——三个词说完"现状→应对→核心能力"
- **正确**：摘要直接列出该层的核心判断，每条一句，结论先行
- **经验教训**（2026-06-13）：L2 标题和摘要写成了思考路径而非结论，读者看半天只知道"你从哪些维度思考了"，但不知道思考结果是什么。报告不是给人展示思考过程，是给人看结论的

### 1.7 摘要中多个并列信息项分行列出
- **禁止**：把四个时间维度（永续、20~30年、10~20年、约等于零）紧凑排成两行
- **正确**：每个并列信息项单独一行，用"·"或序号开头，确保手机竖屏可读
- 颜色高亮仅用于区分核心概念/问题/结论，不用于密集排版

### 1.8 禁止使用"图示/方法/实例"三栏导读格式
- **禁止**：在子卡开头使用"图示 / 方法 / 实例"三栏卡片作为导读
- **原因**：卡片自身的摘要和结论已经直接给出了信息，不需要再用三栏做导读。这是套用麦肯锡报告格式，在本报告的卡片式结构中属于冗余
- **正确**：直接进入内容，用折叠/展开控制信息密度

### 1.9 子卡标题要体现递进关系（洋葱剥皮式）
- **禁止**：子卡标题写"必要层：为什么需要分布式储能"——读者不知道"必要层"从哪来的
- **正确**：1.1 标题给出"为什么必须用电"的结论后，1.2 标题直接衔接到"大量用电→引出分布式储能是新型电力系统咽喉"，1.3 标题再衔接到"分布式储能为什么选电化学（跨尺度+微观内比）"
- **原则**：标题本身就是逐层递进的故事线，不需要在摘要里再写"1.1 讨论了什么，1.2 讨论了什么"

### 1.10 摘要禁止"导引"——不要告诉读者接下来要读什么
- **禁止**："四层追问，每一层给出一个明确的结论"（这是导引，不是结论）
- **禁止**："2.1 从……推演，2.2 论证……，2.3 分析……"（这是写作提纲，不是给读者看的东西）
- **禁止**：子卡摘要写"需要论证×××"——直接给出论证结果
- **正确**：摘要直接给出该层/该子卡的核心判断，每条一句，结论先行。读者不需要知道"你接下来要写什么"，只需要知道"你的结论是什么"

### 1.11 关键词提炼要准确、完整、覆盖主要内容
- **禁止**：提炼的关键词只覆盖部分内容，漏掉重要模块
- **正确**：关键词 = 摘要的再次重点表达，重要的事情说三遍。读者扫一眼关键词就能知道所有子卡大致有什么
- **经验教训**（2026-06-13）：L2 关键词提炼了"三条战线""五派博弈""分布式储能"，但①"三条战线"不准确，应是"三重压力"（需求截流+供给碾压+财务失血）②漏提了"电池银行"（与换电网络共同构成资产运营主体）③"五派"简写只有电池厂能看懂，应写全（电池厂·ICT巨头·一体车企·新势力·传统车企）④漏提"链家重构信任""京东重资产壁垒"跨界对比

### 1.12 L2 标题是战略层标题，必须正面回应该层核心非共识
- **禁止**：L2 标题只写"制造业→资产运营业"而不提"换电"——换电是整个转型的具体承载方式，且是与其他投资机构的非共识所在
- **正确**：L2 标题必须明确写出"从动力电池换电业务开始"的转型路径，因为这是"其他投资人可能都不太一致的判断"
- **原则**：L2 标题 = 报告总标题的回应 + 非共识的具体表达

## 二、信源与引用

### 2.1 外部信源必须加可点击链接
- 所有引用的外部资料（新闻、报告、政策文件）必须在对应位置加上 `<a href="..." target="_blank">` 链接
- 链接样式：使用 `var(--accent)` 颜色 + 下划线
- 格式示例：`[信源 · 新浪财经]` 或 `[信源链接]`

### 2.2 引用原话必须标注来源
- 如果报告正文中引用了某人原话（如曾毓群），必须在**首次出现时**就标注来源，不能藏在深层展开内容中
- 标注格式：`—— 曾毓群，2026.6《财经》杂志年度级别深度独家专访（执行主编马克对话）[信源链接]`
- 同一段原话如果在开篇信号区和 L2 都出现，两处都要标——且开篇那处的标注更重要

### 2.3 不标注内部文档来源
- **禁止**：在正文中写"来自 PBL 的 1.2 章"、"来源：某内部文档"等
- 结论直接写就行，读者不关心你的附件结构

### 2.4 附录B必须有对应链接
- 附录B中的每一条参考资料，如果是公开可获取的，必须加上可点击链接
- 公开资料包括：年报、行业报告、政策文件、新闻报道
- 内部文档（如 PBL框架.md）可以不加链接，但需要标注文件路径

### 2.5 链接必须可验证（自复核机制）
- **绝对禁止**：不加验证地编造链接。所有外部链接在给出前必须满足以下任一条件：
  - 已通过 WebFetch 工具实际抓取页面内容，确认页面存在且内容相关
  - 已通过 WebSearch 确认该 URL 在搜索结果中存在
  - 如果两者都无法做到，**不要给出链接**，改为标注资料名称 + 导航路径说明（如 `catl.com → 投资者关系 → 定期报告`）
- **禁止**：链接到网站首页（如 `catl.com`、`ndrc.gov.cn`）冒充具体文件链接——首页无法验证"某份具体报告/采访"的存在
- **禁止**：编造视频链接（如抖音视频 ID）；视频链接极难验证，除非是官方 YouTube/B站 等有固定 URL 格式的平台
- **经验教训**（2026-06-11）：曾毓群《财经》访谈的先前的链接（新浪财经非官方转载 + 失效抖音视频）在用户点开后无法验证内容，浪费了审阅时间。教训：① 链接必须自己先用 WebFetch 验证过；② 不能用 `stock/relnews` 侧边栏转载替代官方通稿（`/wm/` 路径）；③ 视频链接不可验证时不要放

## 三、布局与结构

### 3.1 长表格不与短内容并列
- 如果左边是简短列表、右边是超长表格，不要用左右双栏布局
- **正确**：改为上下排列，或者把表格折叠

### 3.2 长表格必须折叠
- 超过 6 行的对比表格，在非折叠状态下应折叠
- 折叠按钮上写好"▶ 展开" / "▼ 折叠"
- 表的关键判断和结论在折叠按钮上方直接展示

### 3.3 展开内容多时拆分子卡片
- 如果展开后的 detail 区域内容超过 2 屏，必须拆分为多个子卡片（sublayer）
- 每个子卡有独立标题、摘要、折叠按钮
- 关键判断必须在折叠前（即摘要里）就展示出来

### 3.4 关键判断必须高亮
- **禁止**：关键判断使用普通白字埋没在正文中
- **正确**：使用 `<b style="color:var(--accent)"><u>核心判断：...</u></b>` 高亮关键判断
- 高亮判断必须在折叠前的摘要区域可见

### 3.5 内容超长时拆分更多子卡，层级不固定
- **禁止**：一个子卡展开后塞进大量内容（多张计算表 + 多段定性描述），全部一次性展开导致阅读困难
- **正确**：根据内容实际需要，继续拆分为更深的子卡层级。子卡做几层不确定，由内容量决定
- **正确**：长表格（超过 6 行）默认折叠，表格前的定性描述作为摘要先行展示
- **实现**：使用 `.tbl-wrap.collapsed` 包裹表格，`.tbl-head` 作为折叠标题，`tblToggle(this)` 切换展开/折叠
  ```html
  <div class="tbl-wrap collapsed">
    <div class="tbl-head" onclick="tblToggle(this)"><span class="tbl-arr">▼</span> 表名</div>
    <div class="tbl-body">
      <table>...</table>
      <p>表后说明</p>
    </div>
  </div>
  ```
- **原则**：表格默认折叠 → 读者先看到定性结论 → 需要数据验证时再展开。这是"结论先行"原则在表格展示上的延伸
- **经验教训**（2026-06-13）：3.3 流转基础设施展开后内容极长（多张计算表 + 大量文字），应当将表格默认折叠，并将不同维度拆分为独立子卡

## 四、图表

### 4.1 图表要"一图集大成"
- 不要越画越简单，图表应当是一个浓缩的集大成信息载体
- 图表应包含该层所有关键维度的信息，而不是只选一两个维度

### 4.2 市值图的信息顺序
- **禁止**：直接放市值柱状图（市值=净利×PE，底层数据缺失）
- **正确顺序**：营收路径 → 净利润路径 → PE倍数路径 → 市值路径+概率加权期望
- 读者需要看到"业绩×估值倍数=市值"的完整逻辑链

### 4.3 不要用文字重复图表信息
- 如果图表已经展示了基准/乐观/悲观三种情景的营收倍数，就不需要再用文字写一遍
- 文字应补充图表无法承载的信息（如关键判断、方法论说明）

### 4.4 概率加权必须出现在图表中
- 三情景的概率加权期望值是一个增量信息，必须出现在图表中
- 不要省略概率加权线/柱

## 五、不回避问题

### 5.1 对潜在挑战要正面分析
- 如果逻辑链条中存在明显的潜在挑战（如量子计算对电子计算的挑战、核聚变对电磁力的挑战），必须正面分析
- 不能回避，不能假装不存在
- 分析后给出明确判断（是替代关系还是叠加关系？是百年尺度还是十年尺度？）

## 六、CSS 与交互

### 6.1 链接样式统一
- 所有外部链接：`color:var(--accent); text-decoration:underline`
- 所有内部锚点链接：同样样式，但使用 `href="#id"` 而非 `target="_blank"`

### 6.2 折叠按钮
- 章节级折叠：`onclick="toggle('id', event)"`
- 子卡折叠：`onclick="subtoggle('id', event)"`
- 自定义折叠（如表折叠）：内联 onclick + `style.display` 切换

### 6.3 折叠必须层级独立
- 父级卡片（.layer）的展开/折叠 **绝对不能** 影响子卡片（.sublayer）的展开/折叠状态
- 子卡片的展开/折叠 **绝对不能** 触发父级卡片的 toggle
- 实现要点：
  - `toggle()` 函数中必须用 `ev.target.closest('.subhead')` 过滤掉来自子卡片的点击
  - `subtoggle()` 函数中必须同时调用 `stopPropagation()` + `stopImmediatePropagation()` 阻断冒泡
  - 两个函数分别使用独立的防抖锁（`_toggleLock` vs `_subToggleLock`）
  - 防抖间隔建议 400ms（防止 TRAE 等预览环境的 touch + click 双事件触发）

### 6.4 链接自验证流程
- 每次修改外部链接后，必须在同一轮回复中至少 WebFetch 验证一条链接
- 无法验证的链接 → 降级为纯文本标注 + 导航路径说明
- 优先使用本地文件链接（相对路径），仅在本地文件存在且可读时才给出外部链接作为辅助

### 6.5 摘要关键词高亮
- 卡片摘要（suboneliner）中大面积 `<b>` 加粗等于没加粗——在手机竖屏上视觉区分度极低
- 改为 `<span style="color:var(--xx);font-weight:600">` 用颜色区分不同层级的关键词：
  - `var(--accent)`（蓝）→ 核心概念（如"电磁力""本质认知""同构规律"）
  - `var(--amber)`（橙）→ 引人注意的问题/转折（如"引出新问题""毫秒级实时平衡"）
  - `var(--green)`（绿）→ 正向结论/唯一解（如"分布式储能是唯一解""最优平衡"）
  - `var(--red)`（红）→ 否定/排除（如"集中式储能不能跟随""只能"）
  - `var(--purple)`（紫）→ 远期/特殊概念（如"锂空气电池"）
- 颜色不宜超过 3 种在同一段落中，优先用 accent + amber + green 三色体系

## 七、信源与数据

### 7.1 关键数字必须有可靠信源，且用浮窗标注
- **禁止**：给出精确数值（如"全固态电池衰减降到10%以内""半固态衰减15-20%"）却不标注信源
- **正确**：关键数字必须以浮窗或脚注形式标注信源，浮窗内含具体链接，同时放入附录
- **正确**：如果信源无法验证，降级为"据行业研究数据"并注明范围，不写精确值
- **经验教训**（2026-06-13）：2.3 固态电池衰减数字无信源——宁德时代凝聚态半固态电池循环寿命2000次后容量≥82%（即衰减≤18%），全固态车规级大电芯循环寿命仅700-800次，衰减远超预期

### 7.2 技术时间线必须基于实际采访/公告，不能推测
- **禁止**：写"半固态量产装车2025年""全固态2028年"——这些数字没有可靠来源
- **正确**：引用曾毓群2026.6《财经》采访——全固态是event-driven不是time-driven，宁德全固态研发处在"4"的水平（1-9 scale），2027年小批量生产，2030年前百万级车可能性很小
- **正确**：半固态电池2026下半年小批量装车（宁德时代凝聚态）

### 7.3 避免同一内容在报告多处重复出现
- **禁止**：链家ACN类比同时在2.4和3.3出现
- **正确**：选择一个最适合的位置集中论述，其他地方如需引用，用简短一句+链接锚点即可

## 八、信号解读

### 8.1 不夸大管理层表态，区分"陈述"与"推断"
- **禁止**：把管理层采访中的一句话过度解读为"印证了L2最关键的一条信号"
- **正确**：管理层说的（如"1000站跑出单站盈亏平衡"）作为事实陈述直接引用；分析师的推测（如"电池银行的算账问题"）作为推断单独标注
- **正确**：换电业务核心是两套体系——换电站（物理网络触点）+ 电池银行（资产运营主体），不能只谈换电站不谈电池银行

### 8.2 利好的判断要有持续跟踪的意识
- **禁止**：把"碳酸锂成本下降"当作利好写入报告——这是周期性大宗商品，短暂下降不代表长期趋势
- **禁止**：把"26家车企联盟"当作产业共识——从签约到实际装车还有距离，这是需要持续跟踪的监测指标
- **正确**：区分"已兑现的事实"和"需要跟踪的假设"，后者用监测指标的方式呈现
- **经验教训**（2026-06-13）：宁德时代宜宾枧下窝锂矿用地预审被注销，锂矿复产需1-1.5年，碳酸锂成本不确定性增加——"成本利好"的判断需要重新审视

## 九、竖屏响应式布局

### 9.1 顶层卡片关键词紧凑排列
- L1 等顶层卡片的 4 组关键词（如"永续级·20-30年·10-20年·≈0"）+ 对应解释，加大字号、紧凑排列
- 竖屏：4 组竖向排列；横屏：根据宽度放 1-2 行
- 不要用大段文字描述，用紧凑的关键词+简短解释

### 9.2 竖屏下标题和摘要移到层级标签下方
- 顶层卡片折叠时，竖屏下标题和摘要应挪到"L1 高确定性"标签下方，避免左边空白+页面过长
- 横屏保持现有布局

### 9.3 子卡长文本必须高亮关键词
- 子卡展开后如果文字超过 3 段，必须用颜色高亮（`var(--accent)`/`var(--amber)`/`var(--green)`）标注结构化信息
- 例如：1.1 的"潜在挑战"分信息端、能源端分别论述，每段开头的关键词应高亮
- 原则：读者扫一眼颜色就能抓住结构化脉络

## 十、图表原则

### 10.1 能用图表不用大段文字
- 例如：3.1 的"技术可行性验证：标准化规格覆盖率与车企适配进展"不应是大段文字，应采用表格形式（按规格列示覆盖率、合作车型等）
- 表格天然比文字更清爽、更易扫读

### 10.2 总结/关键判断必须高亮卡片化
- 每层/每子卡最后如果有总结或关键判断，必须用高亮卡片（类似 `.mini-summary`）呈现
- 这是与头部摘要的呼应——看完展开内容后再次强调重点
- 例如：2.4 最后的一句话总结、2.5 最后的核心结论——都应放在高亮卡片中
- **禁止**：开头写"这一层告诉我们什么？"——直接说结论

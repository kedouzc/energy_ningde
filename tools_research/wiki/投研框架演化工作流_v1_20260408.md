# 投资框架演化实验室：Karpathy Wiki 工作指南

> **目标**：用 Wiki 辅助投资框架的探索与演化  
> **现状**：多个框架并行迭代（能量信息框架 v2、四层框架过程版、三通道框架）  
> **策略**：Wiki 作为"框架实验室"，记录演化过程、辅助框架统一  
> **时间**：今天 30 分钟建立工作空间

---

## 你的工作流：框架演化流程

### 日常流程（研究新标的）

```
1. 发现新标的
   ↓
2. 创建案例文件夹（02_案例验证/公司名/）
   ↓
3. 用多个框架分析（创建多个"用X框架分析.md"）
   ↓
4. 对比哪个框架更适合
   ↓
5. 发现框架问题？→ 更新"_待解决问题.md"
   ↓
6. 产生新洞察？→ 更新"_统一框架构想.md"
```

### 每周流程（框架迭代）

```
每周五框架会议（30 分钟）：
1. 回顾本周案例测试的发现
2. 更新"_框架演化路线图.md"
3. 检查"_待解决问题.md"进展
4. 推进关键决策点
5. 规划下周测试案例
```

### 决策流程（关键节点）

```
当达到决策点时：
1. 汇总所有对比分析和案例测试
2. 用"模板 5"进行决策分析
3. 更新"_框架演化路线图.md"
4. 执行决策（统一框架 or 保持分立）
5. 更新所有相关文档
```

### 为什么不需要物理整合？

| 知识库 | 核心功能 | 与投研的关系 | 整合方式 |
|--------|---------|-------------|---------|
| `tools/research` | AI工具方法论 | 提升投研效率 | **逻辑链接**，不迁移 |
| `financial_model_project/mind` | 工程化思维训练 | 培养系统思考 | **逻辑链接**，不迁移 |
| `证券投资/wiki` | 投资知识沉淀 | 主战场 | **优化架构** |
| `证券投资/引擎` | 工具验证 | 框架实践 | **纳入wiki工具层** |

**核心洞察**：分散是**合理的**，形成能力转化链：
```
工程思维(mind) → AI技能(research) → 投研实践(wiki) → 工具验证(引擎)
```

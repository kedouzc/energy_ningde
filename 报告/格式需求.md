# 格式需求

## 关键内容彩色高亮显示：自动语义识别

**html和md的分工**：html负责交互式展示md内容，md负责编写维护内容，颜色格式由html负责。md是纯文字版，不影响作为独立的md文档阅读，人负责通过md维护内容，AI负责html交互渲染自动化。

**色彩标注**：由md导入html时，调用AI自动识别哪些是重要词句（不由人工指定关键字，发挥AI语言模型对语义的理解能力，自动识别哪些词句表达重要含义），并为其添加颜色。以下示例`d:\AI\证券投资\投研\能源\宁德时代\报告\宁德时代_V3.0.html` 之前也不是人工标注的，我只是和AI对话时提了这个需求，没有人工维护任何字典，AI自主完成色彩标注。

**skill中关键词高亮提示定义**：
- 大面积 `<b>` 加粗等于没加粗——在手机竖屏上视觉区分度极低
- 改为用颜色区分不同层级的关键词：
  - accent（蓝）→ 核心概念（如"电磁力""本质认知""同构规律"）
  - amber（橙）→ 引人注意的问题/转折（如"引出新问题""毫秒级实时平衡"）
  - green（绿）→ 正向结论/唯一解（如"分布式储能是唯一解""最优平衡"）
  - red（红）→ 否定/排除（如"集中式储能不能跟随""只能"）
  - purple（紫）→ 远期/特殊概念（如"锂空气电池"）
- 颜色不宜超过 3 种在同一段落中，优先用 accent + amber + green 三色体系

### 以下为错误方案展示：需要人工维护字典

#### 现有 HTML 颜色使用规律（反推结果）

通过分析示例 HTML 中约 60+ 处颜色高亮，全部是人工手写 `<span>` 标签，总结出 5 类语义映射：

| 颜色 | CSS变量 | 语义 | 典型词 |
|:---|:---|:---|:---|
| 红 | `--red` | 风险/负面/阻碍 | 失血、衰退、锁定、被剥夺、尚未、不可控、极高(成本) |
| 绿 | `--green` | 正面/优势/进展 | 转正、加速、最优、唯一、升维、极低(风险) |
| 琥珀 | `--amber` | 关注/不确定/博弈 | 不确定、博弈、风险、不稳定、终极风险 |
| 青 | `--accent` | 关键概念/框架/类比 | 换电网络、电池银行、ACN、"…"引号内容、数字+单位 |
| 紫 | `--purple` | 核心论点 | (极少，用于表格表头) |

**关键发现**：另一财务模型 model.html 没有语义高亮，只有 CSS 类（`.good`/`.bad`/`.warn`）用于数值正负。

#### 方案提案：语义高亮引擎

##### 核心思路

```
MD 纯文本（零标记，可独立阅读）
        │
        ▼
┌──────────────────────────────────┐
│  highlight-engine.js（新模块）     │
│                                  │
│  第一层：结构信号识别              │
│  · 引号 "…" → accent             │
│  · ❌/✅/⚠️ 前缀 → red/green/amber│
│  · 数字+单位 → accent            │
│                                  │
│  第二层：语义词典匹配              │
│  · 5 类词典（各 50-100 词）        │
│  · 短语优先（2-6 字）             │
│  · 最长匹配原则                  │
│                                  │
│  第三层：上下文修正               │
│  · 否定反转："不"/"未"+正面词→red │
│  · 转折加权："但"/"然而"后提高风险权重│
│  · 比较语境："更"+形容词→按形容词分类│
│                                  │
│  冲突消解：结构 > 上下文 > 词典    │
└──────────┬───────────────────────┘
           │
           ▼
带颜色高亮的 HTML
<span style="color:var(--red);font-weight:600">失血</span>
```

##### 模块设计

| 文件 | 职责 |
|:---|:---|
| `common/highlight-engine.js` | 语义识别 + 着色渲染（新模块） |
| `common/md-loader.js` | `mdToHtml()` 中调用引擎（已有，微调） |

引擎暴露一个入口函数：

```javascript
/**
 * 对纯文本进行语义高亮，返回带 <span> 的 HTML
 * @param {string} text - 纯文本（已去除 MD 语法标记）
 * @returns {string} 带 <span style="color:var(--xxx);font-weight:600"> 的 HTML
 */
HighlightEngine.highlight(text)
```

##### 上下文修正规则

| 规则 | 输入 | 输出 | 示例 |
|:---|:---|:---|:---|
| 否定反转 | 不/未 + green词 | red | "不可控" → red |
| 否定反转 | 不/未 + red词 | green | "不衰退" → green |
| 引号标记 | "…" | accent | `"制造业"` → accent |
| Emoji前缀 | ❌ + 任意 | red | `❌ 集中式` → red |
| Emoji前缀 | ✅ + 任意 | green | `✅ 可分布式` → green |
| 数字强调 | 数字+单位 | accent | `10万座` → accent |

##### 提炼 vs 不提炼

| 维度 | 提炼为 `highlight-engine.js` | 不提炼（各 HTML 手写） |
|:---|:---|:---|
| **MD 纯度** | 高，零标记 | 高，同左 |
| **一致性** | 强，所有页面统一 | 弱，各页面可能不一致 |
| **维护** | 集中改词典，全局生效 | 分散，每处单独改 |
| **准确率** | 80-90%（规则覆盖） | 100%（人工标注） |
| **新增内容** | 自动识别，无需操作 | 需人工逐个加 `<span>` |
| **误标处理** | 需调词典或加排除规则 | 不会误标 |
| **文件数** | +1 新文件 | +0 |
| **适用场景** | 大量 MD 动态加载 | 少量固定内容 |

##### 是否需要工作范式指引？

**需要**。指引内容：
1. 五色语义约定（什么内容用什么颜色）
2. 词典维护方法（如何新增/修改词条）
3. 误标处理流程（如何加排除规则）
4. 引擎工作原理和局限性

##### 局限性（需提前知晓）

1. **中文分词**：简易词典匹配，不如专业 NLP 准确
2. **多义消歧**："锁定目标"（accent）vs "被锁定"（red）需上下文规则
3. **复杂语义**：反讽、隐喻无法识别
4. **词典维护**：新领域词汇需手动补充
5. **准确率预期**：约 80-90%，不追求 100%（剩余 10% 可接受为"无高亮"）

## 文件整理的"三条红线"

1. **不动原文件**
   - 业务/资产运营/ 下所有文件保留原位
   - 不批量重命名（文件名是工作记忆）
   - 不删除旧版本（保留作为审计轨迹）

2. **新内容走"三目录"规则**
   - 框架/方法论 → `_方法论索引/`
   - 待吸收的草稿 → `_待吸收区/`
   - 旧版本/暂不用 → `_归档/`

3. **主报告单一来源**
   - 唯一对外文件：`宁德时代_V1.0.html`
   - 修订主报告时，**必须**同步更新 `_方法论索引/02_主报告源材料映射表.md`

## 推荐工作流

### 场景 1：开始新研究（如"宁德储能板块深挖"）
1. 读 `_方法论索引/01_框架拼接指南_V5-V9.md` → 确定框架
2. 读 `宁德时代_V1.0.html` 顶栏+方法论索引卡 → 理解整体
3. 读 `L6 储能深研` 现有内容 → 识别 gap
4. 创建新工作文件 → 放入 `_方法论索引/` 或主目录
5. 完成后**反向更新**主报告对应章节

### 场景 2：修改主报告
1. 读 `_方法论索引/02_主报告源材料映射表.md` → 找到要改的章节
2. 查源材料 → 决定是修订还是大改
3. 修订后**更新映射表**（源材料变了要标注）
4. 重大修改时把上一版复制到 `_归档/`

### 场景 3：清理"散乱"文件
- 三个月内未被任何报告引用 → 移到 `_归档/`
- 内容被新版本完全取代 → 移到 `_归档/` 并写明原因
- **永不删除**（用户可手动删）

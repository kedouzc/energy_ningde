## ⚠️ 三项检查之外，发现两个真实缺口

### 缺口一：`{{topic: ...}}` 引用机制不存在

`框架提案.md` §1.4 写了"章里用 `{{topic: 业务本质_第一性原理拆解}}` 引用，
`build.py` 装配时展开"。但 `inject.py` 的 `TOKEN_RE` 是：

```python
re.compile(r"\{\{\s*([A-Za-z0-9_.]+)\s*(?::\s*([a-z]+)\s*)?\}\}")
```

**只认 ASCII 键名，且冒号后面是格式说明符（`:n`），不是参数。**
所以 `{{topic: 中文名}}` 既匹配不上，也不会被展开。

**判定：不阻塞本轮，归入第 8 步（装配）。** 现在 topics 各自独立成文、章里用普通链接引用即可。
**已写进 `交接.md` 4.3 未做。** 不在这一轮实现——它属于装配层，现在做是提前设计。

### 缺口二：叙述层需要的数，有一部分不在 `facts.json` 里

`facts.json` 装的是**模型算出来的数**（96 个键，`base.*` / `q1–q4.*` / `dcf.*` / `sens.*`）。
但专题里要用的还有一类：**外部引用事实**——

| 例 | 出处 |
|---|---|
| 重资产基建族 EV/EBITDA 区间、资管平台族区间、特斯拉倍数 | `v3.2 §4.1`（2026-08-26，Multiples.vc LTM） |
| 电池占整车成本比例、单车年增收、BaaS 购车成本降幅 | JPM《重卡电动化》§8.3、Table 3 |
| 电池包价格、锂价 | TrendForce 2026-08 |

**它们不是模型输出，`facts.py` 不会生成；但叙述层的裸数字纪律同样管着它们。**

**改成什么**：`facts.json` 增设 **`ext.*` 命名空间**——外部引用事实，每条必须带
`from`（信源 URL 或文件§号）与 `as_of`（抓取日期）。
理由同「2026-09-05i」TCO 引用陷阱：**引用一个时点数，必须写清它是哪个时点的。**

**本轮的处理**：新建的专题里，外部数一律写成 `{{ext.xxx}}` 占位符，
**并在下面列出待补清单**——这样专题从第一天起就是合规的，缺的是 `facts.py` 侧一个新命名空间。
**已写进 `交接.md` 4.3 未做。**
